# Мультиплеер с игроком-хостом — решение и очередь, 18 октября 2026

## Короткий ответ

Кампанию может вести компьютер одного игрока. Отдельный арендуемый игровой
сервер для каждой партии не обязателен. Это уже модель текущего ENet-кода:
`HostNetworkGame` создаёт сервер, клиенты подключаются к нему; правила и
проверка приказов остаются в C# Campaign, не в сервисе лобби.

Но отсутствие аренды и отсутствие внешней инфраструктуры — разные требования.
Ниже **варианты, а не уже подключённые функции**.

| Вариант | Где считается мир | Что требуется снаружи | Ограничение |
| --- | --- | --- | --- |
| Нынешние LAN / прямой IP | У игрока-хоста | Сервис игры не нужен | Для интернета хост должен быть доступен через роутер/провайдера |
| Steam-лобби + P2P/SDR | У игрока-хоста | Steam: поиск, идентичность, соединение/ретрансляция | Steamworks-интеграция и доступность Steam; не автономный режим |
| Собственное обнаружение/P2P | У игрока-хоста | Наш доступный узел согласования; иногда ретранслятор | Самостоятельное размещение тоже инфраструктура и эксплуатация |

Godot описывает проброс UDP-порта для домашнего хоста и поддержку IPv6.
Публичный доступный адрес и настройка firewall могут позволить прямое
соединение. Под CGNAT одного проброса на домашнем роутере недостаточно:
нужно решение на стороне провайдера, доступный IPv6 либо обход/ретрансляция.
Код комнаты лишь помогает найти адрес/идентичность; сам по себе NAT не обходит.
См. [Godot: hosting considerations](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html).

Steam хранит лобби на своих backend-серверах; участники затем подключаются
к назначенному игроку-хосту. SDR предоставляет соединение через Steam P2P API.
Это позволяет не арендовать собственный сервер симуляции, но не означает,
что серверов вообще нет. Open-source GameNetworkingSockets сам по себе
не предоставляет доступ к сети ретрансляторов Valve. Вне Steam условия
дополнительные; не обещать ту же схему любому standalone-билду.
[Лобби Steam](https://partner.steamgames.com/doc/features/multiplayer/matchmaking),
[SDR и ограничения](https://partner.steamgames.com/doc/features/multiplayer/steamdatagramrelay).

## Предпочтительное направление для DoF

Сохранить независимый ENet LAN/IP-режим. Для Steam-сборки добавить опциональные
лобби, приглашения друзей и Steam P2P/SDR. Не менять мировые правила ради
транспорта и не отправлять симуляцию «на Steam». Это рекомендация; транспорт
в данном проходе **не реализован**, Steam-приложение и аккаунты не создавались.

Общий контракт подключения должен передавать сообщения тому же авторитетному
хосту. Транспорт/идентичность отделить от:
- назначения страны и прав участника;
- очереди и проверки кампанийных команд;
- сетевого протокола, отпечатка контента/модов и правил версии;
- имеющихся snapshot/cadence/recovery механизмов.

Не объявлять любой SteamID доверенным приказом: идентичность транспорта должна
сопоставляться с участником и его страной. Не использовать метаданные лобби как
авторитетное состояние кампании. Не переносить мир по сети на каждом кадре.
C# остаётся владельцем сети; F#-правила принимают только значения. Новая
Rust-интеграция для этого не нужна и не запланирована.

## Приёмка будущей реализации

1. Две настоящие машины в разных домашних сетях: создание, приглашение,
   отказ постороннему, выбор страны, старт и одинаковый отпечаток мира.
2. Проверить модовые несовпадения и старую версию протокола до старта партии.
3. Потеря пакетов/соединения, повторное подключение и запрос resync не должны
   дублировать приказы, разрешать чужую страну или повреждать сохранение.
4. LAN/IP остаётся рабочим без Steam; отсутствие сервиса объясняется в UI.
5. При выходе хоста партия не продолжает тайно расходиться у клиентов.
   Автоматический перенос хоста — отдельная механика, пока не обещана.
6. Проверить доступность нужного API в нашем Godot 4.8 .NET, упаковку native
   библиотек и реальную Steam-сборку. Наличие addon-папки не равно интеграции.

Архитектуру всех игр Paradox здесь не утверждаем: наличие игрока-хоста не
доказывает отсутствие серверов поиска/авторизации/ретрансляции. Стоимость
публикации в магазине и условия сервисов не подменяют вопрос аренды игрового
сервера; конкретные условия повторно проверяются перед подключением.
