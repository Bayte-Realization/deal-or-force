## 0. Ответ на вопрос «Ты согласен со Мной?»

**В целом да, но лёгкая только половина работы.**

Что уже есть и правда просто:
- Календарь поддерживает любую дату, включая годы до нашей эры (`HistoricalDate.cs:12-101`, `SimulationCore.cs:53-107`).
- Механики выключаются переключателями. Их 58 в `Defines.Features` (`MechanicFeatures.cs:16-83`) и ещё 16 привязаны к определениям в `FeatureDefines` (`MechanicFeatures.cs:242-252`). Механика может открыться позже, когда сработает триггер с условием на год, технологию или другой переключатель. Это `FeatureUnlocks` в `MechanicFeatures.cs:145-159`. Пример лежит в `mods/_templates/era_features`.
- Здания можно ограничить датой и технологиями (`ConstructionAdmission.cs:14-96`).
- Датированные события есть, и для 1783–1944 годов уже написан контент: `events/60_dated_history.json`, `61_historical_eras.json`.

Чего нет, и это не мелочь:
1. **Эпохи как понятия в игре нет.** Сценарий сейчас — это либо сгенерированный 2024 год, либо замороженный снимок целого сохранения (`world.json`).
2. **Весь контент общий для всех сценариев и загружается один раз за запуск.** Технологии, идеологии, правительства, законы, доктрины, юниты, товары, события и решения не знают, в каком сценарии находятся. Удалить запись мод не может: каталоги сливаются по ключу.
3. **«2024» прошит примерно в 30 местах.** Это папки истории, проверки `ScenarioId == "2024"`, война России и Украины, заданная в коде, калибровка ВВП и таблица войск 2024 года (раздел Б.2).
4. **Доступность по технологии или эпохе есть только у зданий.** У идеологий, правительств, законов, стратегических доктрин, наземных юнитов и товаров такого условия нет совсем.
5. **Определения (defines) нельзя переопределить частично для одного сценария.** Есть только полный снимок `ScenarioRules` (`SaveSystem.cs:151,1097,1261,1471`), и после экспорта он не получает правок баланса.
6. **В сценарии нельзя создать страну с новым тегом.** Генератор строит страны только из таблицы карты. В редакторе поля Tag, Iso, Id и MapIndex заблокированы (`ScenarioInspectorCatalog.cs:96-101`).

Поэтому ниже предлагается не «ещё один world.json», а слой эпох. Сценарий в нём — набор данных: манифест, своя папка истории, своя надстройка контента, патч определений и переключатели. У контента появляется общее правило доступности, а доктрины и идеологии меняются вместе с эпохой через обычную симуляцию, одинаково для всех стран.

Для 1985 года это в основном работа с данными плюс шаги E1–E9 в коде. Для 1836 года и раньше заметно больше кода и баланса (раздел Б.7).

Медиа (часть А) от эпох не зависят. Их стоит сделать первыми: они чинят конвейер файлов модов, а он понадобится и для картинок сценариев.

## А.2. Решения

1. **Медиа — только оформление.** Симуляция поле `media` не читает. В `CampaignFingerprint` и проверку рассинхронизации оно не входит, в сохранение не пишется. Исключение — `DefinitionId` у ожидающего события, см. А.6.
2. **Один реестр — медиатека.** Событие, решение или сценарий ссылается либо на id из медиатеки (`MediaLibraryCatalog`), либо на имя спрайта (`SpriteCatalog`), либо на путь внутри своего пакета. Проверки форматов и лимитов живут в одном месте.
3. **Видео — только Ogg Theora (`.ogv`).** Плеер: `new VideoStreamTheora { File = путь }` без импорта. MP4 и WebM требуют GDExtension, а это риск для Android, поэтому их принимает только конвертер.
4. **GIF поддерживаем двумя способами сразу**, обоснование в А.4:
   - **встроенный декодер GIF89a на C#.** Работает в игре на любой платформе, без зависимостей. Каждую GIF декодирует один раз при загрузке в один спрайт-лист.
   - **конвертер `Tools/convert-media.ps1` на ffmpeg** для авторов на ПК. Превращает GIF, MP4 и WebM в `.ogv` или в лист кадров с JSON и сразу проверяет лимиты.
5. **Анимированный WebP и APNG не поддерживаются.** Показывается первый кадр, в журнал мода пишется предупреждение со ссылкой на конвертер.
6. **Анимацию рисует свой Control (`AnimatedPicture`)** по одному GPU-листу через смену области (`DrawTextureRectRegion`). `AnimatedTexture` не используем: у неё предел в 256 кадров, кадры одного размера, нет `AtlasTexture`, и сама документация называет её неэффективной на современных рендерерах.

## А.3. Формат данных

### Поле `media` — одинаковое для событий, решений и сценариев

Короткая форма — строка. Она ищется сначала как id в медиатеке, потом как имя спрайта, потом как путь внутри пакета:

```json
"media": "tank_parade"
```

Полная форма:

```json
"media": {
  "file": "gfx/events/tank_parade.gif",   // путь от корня пакета (мода или сценария); или
  "id": "tank_parade",                    // id медиатеки / имя спрайта (взаимоисключающе с file)
  "poster": "gfx/events/tank_parade.jpg", // неподвижный кадр: пока грузится, при выключенной анимации, при ошибке
  "loop": true,                           // по умолчанию true для анимации, false для видео
  "fit": "cover",                         // cover | contain (cover = как сейчас KeepAspectCovered)
  "audio": false,                         // звук видео; по умолчанию false в событиях и решениях
  "max_seconds": 20                       // необязательный обрез видео в событии
}
```

- Старое поле `"picture"` у событий работает как раньше. Если заданы оба поля, `media` важнее, а `picture` используется как постер, когда постера нет.
- Тип определяется по расширению: `.png`, `.jpg`, `.webp` (первый кадр) — картинка; `.gif` — анимация через декодер; `.ogv` — видео. Для листа кадров нужно объявление в `SpriteCatalog` или медиатеке (ниже).
- Пути разрешаются от корня пакета, который объявил запись, а не от `res://game/gfx` (сейчас ошибка в `EventPictures.cs:30-37`). Выйти за пределы пакета нельзя: та же проверка, что в `ScenarioLibrary.SafePath` (`ScenarioLibrary.cs:41-47`).

### Анимация листом кадров (без GIF)

Объявление спрайта расширяем. Ключ `frames` уже есть, добавляются `columns`, `fps` и `loop`:

```json
// gfx/sprites/*.json или presentation/*.json мода
"tank_parade": { "file": "gfx/anim/tank_parade_sheet.png", "frames": 48, "columns": 8, "fps": 12, "loop": true }
```

### Медиатека

В `MediaLibraryCatalog` добавляется вид `Animation` (`.gif` или лист кадров), а у `Video` появляются поля `poster` и `loop`. Конвертер пишет такие записи сам.

### Сценарий (`scenario.json`)

```json
"media": { "file": "gfx/scenario_1985.jpg" },        // картинка в списке сценариев
"intro": { "file": "video/intro_1985.ogv", "skippable": true }  // один раз при старте кампании
```

### Где показывать

В первую очередь:
1. **Окно события:** полоса картинки высотой 170 px (`EventUI.cs:56-62`). При скрытии окна плеер останавливается и освобождается (`EventUI.cs:87, 146`).
2. **Карточка решения:** верх `RefreshAgendaDetail` (`DecisionUI.cs:228`). Обещания и цели используют те же строки `AgendaWorkspace.Entry` и получают поле заодно.
3. **Сценарий:** панель деталей (`ScenarioWorkbenchUI.cs:242`) и вступительное видео при старте.

Во вторую очередь:
4. **Экран загрузки:** только картинки или лёгкий лист кадров не выше 12 fps. Видео там не показываем: загрузка занимает процессор, Theora будет дёргаться и замедлит загрузку.
5. **Новости и хроника, учёт движения:** только неподвижная миниатюра. Анимация в списках — лишняя нагрузка на телефоне.

Чего не делаем совсем: видео и анимацию на слое карты и глобуса.

## А.4. GIF: почему и декодер, и конвертер

| Вариант | Плюсы | Минусы |
|---|---|---|
| Только конвертер (ffmpeg) | Нет кода в игре, файлы заранее оптимальны | Моддер обязан ставить ffmpeg. Положенная в папку GIF «молча не работает». На телефоне конвертер не запустить. |
| Только декодер в игре | Моддер просто кладёт GIF, работает везде, включая Android | Декодирование стоит процессорного времени и памяти. Большую GIF надо ужимать на лету. |
| **Оба (выбор)** | Простой путь работает всегда, качественный путь доступен | Два кода, но оба маленькие |

Почему декодер выдержит телефон:
- GIF89a — это LZW, палитра, прозрачность, режимы удаления кадра и задержки. Это около 300 строк чистого C# без Godot.
- Код кладётся в `Scripts/Media/GifDecoder.cs`, возвращает `byte[]` RGBA и метаданные, поэтому его можно тестировать в `Tools/FormableTests` без движка.
- Декодирование идёт в фоновом потоке (`Task.Run`). Пока оно идёт, показывается постер. В главном потоке вызывается только `ImageTexture.CreateFromImage`.
- Задержка кадра 0–1 сотых секунды считается как 10, как в браузерах.
- Если GIF больше лимитов, декодер сначала ужимает её сам: уменьшает размер в 2 или 4 раза, пропускает кадры и суммирует их задержки. Отказ и постер — только если и этого мало. В журнал мода пишется строка вида `MEDIA_FIT <файл>: 960x540x180 -> 480x270x60`.

Конвертер `Tools/convert-media.ps1`:
```
-In <файл.gif|.mp4|.webm> -To ogv|sheet [-Target android|desktop] [-Out <папка>]
```
- `ogv`: `ffmpeg -i in -vf scale=...:-2,fps=30 -c:v libtheora -q:v 6 -c:a libvorbis out.ogv`. Файл Theora с расширением `.ogg` переименовывается в `.ogv` — этого требует Godot.
- `sheet`: `-vf fps=12,scale=...,tile=CxR` даёт `sheet.png` плюс объявление спрайта в JSON.
- В конце конвертер проверяет лимиты (А.5) и печатает итог в строке `MEDIA_CONVERT ok|over-cap ...`.

## А.5. Лимиты памяти и производительности

Лимиты проверяются при загрузке. Если превышение остаётся даже после ужатия, игра пишет ошибку мода и показывает постер или картинку. Падения нет.

| Лимит | ПК | Android |
|---|---|---|
| Длинная сторона кадра анимации | 1024 px | 512 px |
| Кадров в анимации | 120 | 120 |
| Длительность анимации | 15 с | 15 с |
| Размер листа кадров | 4096×4096 | 2048×2048 |
| Декодированный RGBA на одну анимацию | 32 МБ | 16 МБ |
| Всего декодированных анимаций в кеше (LRU) | 96 МБ | 32 МБ |
| Видео: разрешение | ≤1280×720 | ≤854×480 |
| Видео: fps | ≤30 | ≤30 |
| Видео в событии или решении | ≤60 с | ≤60 с |
| Вступление сценария | ≤180 с | ≤180 с |
| Видео: размер файла | ≤50 МБ | ≤50 МБ |
| Одновременно играющих видео | 1 | 1 |

Для ориентира: кадр 480×270 в RGBA занимает 0,5 МБ, поэтому 32 кадра — 16 МБ (лимит Android), а 48 кадров — около 25 МБ.

Ещё три правила:
- Анимация тикает только пока Control виден. При скрытии она останавливается, после закрытия окна текстура уходит в LRU-кеш.
- Theora декодируется на процессоре. Если видео стартует, а ему нужно больше, чем позволяет бюджет, игра его не начинает и показывает постер. Бюджет: на Android один плеер и пауза симуляции не обязательна, но окно события модальное.

**Настройка игрока** — в разделе «Графика / доступность»:
- «Анимация в картинках: Вкл / Только первый кадр / Выкл»;
- «Видео: Вкл / Выкл»;
- «Вступления сценариев: Показывать / Не показывать».

Системное «уменьшить движение», если Godot его отдаёт, по умолчанию включает вариант «Только первый кадр».

Существующая настройка «сгенерированная графика загрузки» должна прятать только сгенерированные картинки по умолчанию, а не авторскую картинку сценария (`ScenarioWorkbenchUI.cs:726`).

## Б.3. Модель: сценарий, надстройка, эпоха, доступность

### Манифест сценария, версия 2

`scenarios/<id>/scenario.json`. Все новые поля необязательные. Манифест 2024 года без них работает как раньше.

```json
{
  "id": "1985",
  "name": "Мир в 1985 году",
  "description": "...",
  "order": 10,
  "start": "1985-03-11",
  "player_country": "SOV",

  "history": "1985",                 // папки history/*/1985 (в базе, в модах и в папке сценария)
  "ownership": "history/provinces/1985/ownership.csv",   // путь от корня сценария
  "world": "",                       // необязательно: снимок world.json по-прежнему поддерживается

  "eras": ["late_cold_war"],         // эра на старте; дальше эры меняет симуляция (Б.5)
  "era_set": "modern_history",       // набор эр, по которым мир может двигаться дальше

  "features": { "drones": false, "nuclear_posture": true },
  "feature_unlocks": { "drones": "tech_uav_reconnaissance_any" },
  "defines": { "StartYear": 1985, "SomeConstructionCost": 0.8 },   // ПАТЧ поверх общих определений

  "content": "content/",             // надстройка контента: common/, events/, localization/, gfx/
  "requires_mods": [],
  "flags": { "seeds_factions": true, "repairs_territories": true },

  "media": { "file": "gfx/scenario_1985.jpg" },
  "intro": { "file": "video/intro.ogv" }
}
```

### Надстройка контента сценария

Это главное архитектурное решение. Папка `content/` сценария — ещё один слой поверх базы и модов, но включается **только в этом сценарии**:
- перед созданием `Campaign` все каталоги сбрасываются (`ResetCatalog`) и грузятся заново как база + моды + надстройка;
- при выходе в меню они сбрасываются обратно.

Это снимает сразу три проблемы:
- 1985 год может добавить деревья технологий 1985→2024 и поменять `requires` у существующих технологий будущего, не трогая 2024 год;
- историческим событиям не нужно в каждом триггере проверять «не 2024 ли сейчас»;
- общий контент модов не протекает между сценариями.

Удаление записей: надстройка может указать `"remove": true` у записи. Это отдельный шаг E4b. Пока его нет, достаточно правила доступности (ниже), которое прячет запись.

Сохранение сценария с надстройкой хранит `ScenarioId` и хеш надстройки. При загрузке надстройка применяется **до** чтения сохранения. Если сценария нет, игра отказывает с понятным сообщением, как при отсутствии нужного мода. Хеш надстройки входит в проверку сессии мультиплеера.

### Общее правило доступности `available`

Это обобщение `BuildingRules` (`ConstructionAdmission.cs:14-96`). Блок можно поставить у технологии, юнита, идеологии, правительства, закона, стратегической и тактической доктрины, товара из данных, здания, решения, события и организации:

```json
"available": {
  "eras": ["late_cold_war", "post_cold_war"],   // хотя бы одна из эр мира активна
  "from": "1982", "until": "2005-12-31",         // HistoricalDate, до н. э. разрешено
  "requires_technologies": ["tech_microprocessors"],  // для страны
  "trigger": "some_scripted_trigger"             // по стране; необязательно
}
```

- Нет блока — запись доступна всегда. Поэтому 2024 год, где блоков нет, не меняется.
- `eras`, `from` и `until` проверяются по миру. `requires_technologies` и `trigger` проверяются по стране. Результат детерминированный, страны перебираются в порядке id.
- Один разборщик и одна функция `Availability.IsAvailable(campaign, nation, rule)`. Подключение к каждому каталогу — отдельный подшаг с проверкой отпечатка.

### Эпохи: каталог `common/eras/*.json`

```json
"late_cold_war": {
  "set": "modern_history",
  "order": 40,
  "from": "1979",                         // раньше этой даты эра не наступит
  "begins_when": "era_post_detente",      // необязательный мировой триггер; без него — по дате
  "features": { "drones": false },        // что эра включает или выключает при наступлении
  "defines": { },                         // патч определений на время эры (осторожно: см. Б.6)
  "names": { "ideology.liberalism": "ideology.liberalism.cold_war" }  // переименования по эре
}
```

- **Мировая эра — одна на всех.** Это `Campaign.EraIds`, по умолчанию пустой список. Раз в день, как `EvaluateFeatureUnlocks` (`MechanicFeatures.cs:145-159`), проход проверяет следующую эру набора: дата наступила и триггер `begins_when` выполнен.
- `begins_when` — мировой триггер: «доля мирового ВВП у стран с технологией X ≥ 30 %», «ни одна из пяти крупнейших держав не держит идеологию Y» и подобное. Для этого в `ScriptedValues` нужны мировые значения (`world.gdp_share_with_technology.<id>`, `world.ideology_share.<id>`). Так эпоха наступает из хода симуляции, а не по скрипту, и в каждой кампании в свой день.
- Наступление эры: включаются её `features`, становится доступен контент с её тегом, выходит новость (с `media`, связь с частью А) и пишется строка в хронику.
- В 2024 году набор эр не задан, проход ничего не делает, и `EraIds` не попадает в отпечаток (приём `LateBuiltIns`).

## Б.4. Как идеологии и доктрины меняются с эпохами

Ниже предложенные правила, одинаковые для всех стран, через симуляцию.

**Идеологии**
- `available` прячет идеологию из выбора и с выборов.
- `successor`: если идеология стала недоступна, её поддержка в каждой стране каждую неделю перетекает в преемника с долей `Defines.IdeologyFadeWeekly`. Пример: `"successor": "national_conservatism"`.
- Если правящая идеология недоступна, это не мгновенная смена, а давление. Есть событие из данных «идеология устарела», а на ближайших выборах или при перевороте выбирается из доступных.
- `era_appeal`: множитель привлекательности по эрам, например `{"late_cold_war": 1.0, "post_cold_war": 0.6}`. Это мягкое «угасание» без запрета, и оно же работает внутри одной эры.
- Переименование по эре — через `names` у эры. Это ключи локализации, без новой записи: «либерализм» в 1836 году описан иначе, чем в 2024.

**Доктрины** (стратегические — `StrategicDoctrines.cs`, тактические — `TacticalDoctrines.cs:59,384-410`)
- `available.requires_technologies` или `eras` открывают новые доктрины. Например, доктрина сетецентрической войны открывается технологией ГЛОНАСС/GPS и цифровой связи.
- `obsolete_in_eras` + `replaced_by`: устаревшая доктрина остаётся у страны, но получает растущий штраф к модификаторам до реформы. Политическая цена реформы уже есть (`political_cost`).
- ИИ выбирает доктрины только из доступных, существующей логикой.

**Технологии**
- `available.eras` ограничивает дерево эпохой. Стартовые технологии страны задаются ключом `technologies` в `history/countries/<папка>`, сейчас такого ключа нет.
- Эффект `add_technology` для событий: сейчас `technology.*` можно только читать.
- Технология — главный путь для юнитов, доктрин, законов и зданий: у них появляется `requires_technologies`.

**Глобальное и национальное.** `FeatureUnlocks` открывает механику всем сразу: одна страна изобрела авиацию — авиация есть у всех. Это нормально для механики (окна, команды), но конкретный юнит, доктрина или здание должны требовать технологию **страны** через `available.requires_technologies`. Так неравномерность 1836 года (Европа против остального мира) сохраняется.

## Б.5. Старые сохранения и отпечаток 2024 года

Правила, которые проверяются на каждом шаге:
1. **Каждое новое поле имеет умолчание «как было».** `HistoryFolder = "2024"`, `EraIds = []`, `available` = null, признаки сценария 2024 года — `true`.
2. **Новое состояние входит в отпечаток только при значении не по умолчанию** (как `LateBuiltIns`, `CampaignFingerprint.cs:388-390`).
3. **В 2024 году никакой новый проход не тратит случайные числа** (`Random.State` не меняется).
4. **Старые сохранения** без `ScenarioId` загружаются как 2024 (`SaveSystem.cs:1086`). Старые world.json сценарии с полным `ScenarioRules` продолжают работать. Если у такого сценария есть ещё и патч `defines`, патч ложится поверх снимка.
5. **Сохранение сценария не 2024 года** по-прежнему пишет действующие определения как `ScenarioRules` (`SaveSystem.cs:1261`). Патч сценария при этом «запекается» в сохранение, и это правильно: правки баланса не должны менять идущую кампанию.

Эталоны снимаются **до начала рефакторинга (шаг E0)**:
- `CampaignFingerprint.Of` для 2024 года с сидами 1 и 7 на день 0, 30 и 365;
- полный вывод `Tools/SimBench 365 1 --soak` и его хеш;
- корпус старых сохранений, включая сохранения из `reports/`, прогнанный через `FormableTests --replay-save` на 30 дней с итоговым отпечатком.

После каждого шага все эталоны должны совпасть бит в бит. Если эталон сдвинулся, шаг не принимается, пока не найдена причина. Это правило ClaudeStateFingerprintTests: сообщение называет полученное число.

## Б.7. 1985 год — первый полигон

### Почему 1985
- Карта и регионы современные, и это почти не мешает.
- Деньги в долларах, механики почти все уместны: DEFCON и ядерное сдерживание даже нужнее.

- Дерево 1985→2024 короткое и хорошо проверяется: к 2024 году мир должен прийти примерно к тому, что есть в базовом сценарии.

## Б.9. Руководство для владельца «Как сделать свой сценарий» (план)

1. **Что такое сценарий.** Манифест, папка истории, надстройка контента, эры. Чем он отличается от world.json: снимок против данных, и почему данные лучше — они переживают правки баланса и смену версии карты и легче для Android.
2. **Быстрый старт.** Скопировать шаблон `mods/_templates/scenario_minimal` (сделать вместе с E1), поменять id, имя и дату, запустить.
3. **Карта.** Мастерская: копия 2024 года, добавить страну, сменить тег, покрасить провинции, сохранить. Скрипт слияния тегов. Проверка «провинции без владельца».
4. **Страны.** Правительство, идеология, правитель, население, ВВП, стартовые технологии; цвет и флаг.
5. **Дипломатия и войны.** Организации, союзы, подданство, идущие конфликты.
6. **Армии и флоты.**
7. **Технологии и эпохи.** Как написать дерево. Как поставить `available`. Как эпоха наступает по дате и мировому условию. Как стыковать дерево с технологиями будущего.
8. **Доктрины и идеологии по эпохам.** `successor`, `era_appeal`, `obsolete_in_eras`, переименования.
9. **Механики и определения.** `features`, `feature_unlocks`, патч `defines`. Какие определения трогать осторожно: деньги и стоимость строительства.
10. **События и решения.** Датированные и органические, принцип «не скриптовать историю». Ссылки только на существующие теги.
11. **Картинки, гифки, видео.** Часть А: поле `media`, конвертер, лимиты.
12. **Проверка.**
    - `FormableTests --scenario-only <id>`;
    - `SimBench 1825 <сид> --scenario <id> --soak` и `--wars`;
    - `ContentLint -Fail`;
    - снимки через Godot MCP Pro.
13. **Частые ошибки.** Тег, который не совпадает. `.ogg` вместо `.ogv`. Технология без пути к ней. Эра, которая никогда не наступает. Экономика с отрицательным бюджетом с первого дня.
