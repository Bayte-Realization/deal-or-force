# Нативный Luau: экспериментальный языковой адаптер

Это второй путь Luau, отличный от изолированного `luau_worker`: `.lua` загружается
Godot как ресурс `Script`, прикрепляется к объекту и имеет собственное состояние
экземпляра. Форк Godot не нужен. Проверенная конфигурация: Godot **4.7.2 .NET**,
Windows x86_64. Поддержка других платформ, Godot 4.8 и экспортного билда не заявляется.

## Установка

В корне проекта:

```powershell
& Tools/LanguageAdapters/install-luau.ps1 -Activate
```

Нужны `git`, `uv` и инструменты C++ Visual Studio. Сборка использует изолированный
SCons 4.11.1, не меняет системный PATH, настройки проекта или установленный Godot.
Перезапустите редактор самостоятельно, когда удобно: работающий редактор установщик
не закрывает. Без `-Activate` копируется DLL, но новый дескриптор не активируется.
Уже существующая активация при этом не отключается.

Источник: MIT-проект [Fumohouse/godot-luau-script](https://github.com/Fumohouse/godot-luau-script),
ревизия `7942ce6def8023596ca0cb8d819b032eb40a4bce`, godot-cpp
`714c9e2c165db2dcb7e6ea57e62a04204d3cfbfa`, Luau
`e0b55a9cb1857bc699a20f0aa3099c7a495a0152`. Upstream архивирован: это существенная
причина держать адаптер экспериментальным, а не обязательной частью игры.
Лицензии устанавливаются рядом с библиотекой. Иконки upstream не копируются.

Применяется наш патч `Tools/LanguageAdapters/patches/builtin-vararg-return.patch`:
встроенные vararg-методы должны проверять отсутствие результата как `-1`, а не
как тип Variant/NIL. Иначе `Callable.Call` вызывает функцию, но теряет её результат.
Установщик проверяет именно этот патч и отказывается собирать посторонние правки.
SHA256 проверенной DLL с патчем:
`8FC1FE101960873DD099C11BB756146442E62AD6609CB4522DCFD5E0A7090FF4`.
Иная среда сборки может дать другой хеш; это запись проверенного артефакта, не подпись.

Бинарник и активный `.gdextension` локальные, игнорируются Git. В репозитории
хранятся установщик, патч, лицензии и `.gdextension.in`. Поэтому клонирование
репозитория само по себе не устанавливает нативный код. Без Luau-мода игра не
требует адаптер. Нельзя удалять DLL, пока процесс Godot её использует.

## Мод кампании

Скопируйте `mods/_templates/luau_engine` в отдельный каталог `mods/`, измените `id`
и включите мод. Шаблон выключен по умолчанию. Манифест:

```json
{
  "id": "my_luau_campaign",
  "name": "My Luau campaign",
  "enabled": true,
  "engine_script_entry": "corecode/main.lua"
}
```

Входной скрипт должен объявлять класс `RefCounted` и зарегистрированный `on_load`.
Скрипты узлов сцены в качестве входа мода отклоняются. Расширение здесь `.lua`,
не `.luau` worker-скрипта. Не комбинируйте несколько языковых входов без необходимости:
каждый указанный backend загружается отдельно и может выполнить изменения дважды.

```lua
--- @class
--- @extends RefCounted
local Mod = {}
local ModClass = gdclass(Mod)

--- @registerMethod
function Mod:on_load(api): boolean
    api:Get("log"):Call("Luau mod ready")
    return true
end

--- @registerMethod
function Mod:on_day_advanced(api): boolean
    local day: number = api:Get("get_day"):Call()
    if day == 365 then
        api:Get("set_feature"):Call("aviation", true)
    end
    return true
end

return ModClass
```

Хуки: обязательный `on_load`, необязательные `on_campaign_created` и
`on_day_advanced`. **Каждый существующий хук обязан вернуть `true`.** При `false`,
пустом результате или ошибке VM загрузчик записывает ошибку и отключает этот
экземпляр. Ошибочный ежедневный хук не спамит следующие дни. Уже выполненные
изменения не откатываются: эти хуки не транзакция. При новой кампании экземпляры
создаются заново; пользовательское состояние Luau пока не сохраняется в сейв.

## Доступ к кампании

Передаётся read-only Godot `Dictionary` с явно разрешёнными `Callable`, а не
полный объект `ModApi`. Чтение: `api:Get("имя"):Call(аргументы)`.
`api["имя"]` для этого адаптера не подходит. Общий `Object.Call` по-прежнему
запрещён для USER-потоков; разрешение INTERNAL не повышается.

| Функция | Аргументы | Результат |
|---|---|---|
| `log` | строка | нет |
| `get_day` | нет | номер дня |
| `get_date` | нет | строка даты |
| `feature_enabled` | id механики | bool |
| `set_feature` | id, bool | bool |
| `get_nation` | тег | Dictionary со снимком страны |
| `set_nation_number` | тег, поле, число | bool |
| `get_define` | имя, запасное число | число |
| `set_define` | имя, число | bool |
| `get_province_terrain` | id провинции | Dictionary со снимком |

Ограничения значений и полей те же, что у `ModApi`; новые полномочия добавляются
явно в `EngineScriptMod.CreateApi`. Для вложенных Dictionary тоже используется
`:Get()`. Для `get_define` запасное значение нужно передавать явно.

## Проверки и ограничения

Нативная проверка:

```powershell
& 'C:/GodotEngineNet/Godot_v4.7.2-stable_mono_win64_console.exe' --headless --path . --script Tools/LanguageAdapters/luau_probe.gd --quit-after 120
```

Проверены регистрация ScriptLanguageExtension, типизированный вызов метода,
отдельное состояние двух экземпляров, возврат bool/числа через Callable и
read-only возможности. Итоговый процесс завершился с кодом 0.
В реальной кампании проверены чтение дня, переключение авиации с восстановлением,
хуки создания/нового дня и нормальное завершение с кодом 0. Отдельный отрицательный
прогон отключил мод после `false` на втором ежедневном вызове: до дня 83
повторных вызовов этого мода не было. Проверки использовали несохранённую кампанию.

Обнаружено ограничение upstream: **переданные в Luau замыкания GDScript могут
привести к нативному падению при завершении процесса**. Контроль регистрации и
обычных нативных Callable завершался нормально. Наш мост использует C# Callable,
а не такие замыкания; его штатный выход проверен отдельно. Полную безопасную
совместимость всех сочетаний языков не обещаем. Не передавайте GDScript closures.

Это доверенный нативный код, не OS-песочница. У этого in-process пути нет внешнего
worker-deadline: бесконечный цикл или ошибка библиотеки могут подвесить/уронить
игру. Для недоверенного экспериментального контента предпочтительнее worker
с таймаутом, но и worker-процесс сам по себе не является OS-песочницей.
Экспериментальные engine-script моды отключены в кампании с несколькими HumanSeats.
Свойства, сигналы, редактор, горячая перезагрузка и release/export требуют отдельной
регрессии; работоспособность этих частей upstream не следует из наших четырёх проверок.

### Release 4.8 dev7: проверка 6 октября

Отдельная проверка официального release-шаблона выявила `0xC0000374` (повреждение
кучи) при завершении даже обычного меню с локальной редакторской DLL. Пройденные
проверки в редакторе не подтверждают этот сценарий. Поэтому `Tools/build.ps1`
по умолчанию исключает нативную Luau DLL и её `.gdextension` только из staging-копии;
установленный адаптер рабочего редактора остаётся на месте. Явный параметр
`-IncludeExperimentalNativeLuau` предназначен для дальнейшего эксперимента, не
для объявления этой комбинации стабильной. Luau worker этим не отключается.

`Tools/verify-build.ps1` проверяет реальный EXE и его exit code. Одного сообщения
`EXPORT_VERIFY failures=0` недостаточно: авария может произойти после него при
освобождении нативных ресурсов.
