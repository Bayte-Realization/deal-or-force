# Языки расширений: рабочий первый шаг и границы

## Реально доступно сейчас

Основная симуляция — C#, интерфейс и инструменты Godot — C#/GDScript, простой контент — JSON/PNG. Все игровые изменения должны идти через один экземпляр кампании и её команды, а не через параллельные миры на каждом языке.

Добавлен выключенный по умолчанию `mods/_templates/fsharp_mod`. Он реализует существующий `IGlobalityMod` и использует тот же `corecode_assembly`, что C#. Отдельный загрузчик или форк движка для этого не нужны. Проверка `Tools/ManagedModTests` компилирует DLL, находит класс отражением, создаёт его и вызывает три настоящих хука с `ModContext`.

Это первый минимальный пример, **не полный F# SDK**: загрузчик пока не разрешает произвольные зависимости отдельно для каждого мода. Обобщённая работа FSharp.Core и сторонних пакетов в экспортированной игре требует отдельной реализации и проверки. Пример не включается автоматически и не меняет баланс.

## Предлагаемые следующие реализации — пока не подключены

| Язык | Где полезен | Способ подключения |
|---|---|---|
| F# | чистые правила экономики, анализ, проверяемые преобразования данных | тот же .NET-контракт; затем разрешение зависимостей и проверка экспортированной игры |
| Rust | компилятор карты, геометрия, измеренные горячие участки | сначала отдельный инструмент; для игрового ядра — версионированный C ABI или GDExtension |
| Go | сервер лобби, инструменты модов, обработка журналов | отдельный процесс с ограниченным версионированным протоколом; не второй симуляционный тик |
| Luau | лёгкие сценарные правила, условия активации механик и события | настоящая встроенная VM Luau с ограниченным API команд, памятью и бюджетом выполнения |
| GDScript | сцены, визуальные эффекты и редакторские инструменты | существующий Godot; обычные GDScript-моды тоже являются доверенным кодом |

Наличие файлов с расширениями `.rs`, `.go` или `.luau` само по себе не считается интеграцией. Lua-совместимая библиотека не считается реализацией Luau.

## Контракт и безопасность

Нативные и .NET-моды — доверенный код с правами процесса игры, не «безопасный лайт-моддинг». Для лёгких сценариев нужны изоляция, запрет файлов/сети/процессов по умолчанию, лимит памяти и инструкций, фиксированный источник случайности и время кампании вместо системных часов. Предкомпилированный чужой bytecode нельзя принимать как проверенный исходный код.

Rust/Go-работник должен получать снимок данных с номером версии и возвращать результат без самостоятельной записи в кампанию. Хост проверяет размер, диапазоны и полномочия и применяет результат на границе тика. Для сетевой игры дополнительно нужны одинаковые версии модов, канонический порядок результатов и тест повторяемости. Обычный отдельный процесс не является OS-песочницей.

## Почему сейчас не форк Godot

В рассматриваемых задачах пока нет подтверждённого ограничения ядра движка: F# использует .NET, а внешние нативные расширения предусмотрены GDExtension. Это архитектурный вывод для нашей игры, не обещание совместимости любых сторонних биндингов. Форк стоит обсуждать после воспроизводимого ограничения движка, которое нельзя решить расширением, и оценки стоимости поддержки собственных редактора и экспортных шаблонов.

Первичные источники: [GDExtension](https://docs.godotengine.org/en/stable/engine_details/engine_api/gdextension/index.html), [.NET-библиотеки на C# и F#](https://learn.microsoft.com/en-us/dotnet/core/tutorials/libraries), [песочница Luau](https://luau.org/sandbox/).
