# Персонажи и портреты: работающий срез моддинга

Этот контракт охватывает **главу государства, главу правительства и министров**.
Это не полноценный реестр всех живущих/умерших NPC: семьи, отношения, заключение,
произвольные биографии и постоянные ID персонажей пока не реализованы этим срезом.
Corecode-моды остаются отдельным расширяемым уровнем, не заменяются этими полями.

## Портрет без кода и без Godot Editor

В редакторе страны есть списки портретов главы государства/правительства и живой
предпросмотр. Сохранение само создаёт `history/rulers` в выбранном моде; в файловую
структуру вручную лезть не нужно. Снимок из редактора не назначает человека в
текущую кампанию: для игры со стартовыми данными мод включается перед новой партией.
Импорт внешнего изображения перетаскиванием/диалогом пока не добавлен этим срезом;
свой файл сначала нужно положить в gfx/leaders мода, затем перечитать мод.

Положите `my_portrait.png` в `gfx/leaders/` своего мода. Имя файла без расширения —
ID спрайта `my_portrait`. Для обычных loose-модов используйте PNG/JPEG/WebP;
предварительный импорт в редакторе не нужен. Существующий вариант
`leader_<имя_строчными_с_подчёркиваниями>.png` продолжает работать.

Для отдельного ID у файла есть обычная декларация спрайтов JSON или YAML:

```yaml
# gfx/90_people.yml — пути относительно gfx/ данного мода
sprites:
  my_civilian_portrait: leaders/civilian.png
  my_uniform_portrait: leaders/uniform.png
```

В `history/rulers/` у страны доступны `state_portrait`, `gov_portrait`, а у записи
министра — `portrait`. Это ID спрайта, не абсолютный путь и не URL. Файл портрета
может принадлежать любому включённому моду. Кадр сохраняет пропорции и обрезает края;
для читаемости готовьте вертикальный портрет, важное лицо не помещайте у краёв.
При отсутствии картинки используется прежний поиск по имени, затем силуэт.
Огромное loose-изображение уменьшается до 512 px по большей стороне.

## Событие/решение меняет действующего персонажа

В обычный `effects` добавляется структурированный объект. JSON/YAML эквивалентны:

```yaml
effects:
  head_of_state:
    name: Example Leader
    age: 45
    trait: reformer
    portrait: my_civilian_portrait
  head_of_government:
    name: Example Prime Minister
    age: 42
    portrait: my_uniform_portrait
```

Можно передать **только** `portrait` или `trait`, не назначая другого человека.
`portrait: ""` возвращает автоматический выбор. Новый человек не наследует чужую
фотографию: привязка хранится по имени и году рождения, а не по президентскому креслу.
Это не обещание устойчивого ID при переименовании: у переименованного персонажа
повторно указывайте портрет. Разные одноимённые люди одного года рождения в одной
стране пока не различаются — ограничение нынешней модели, не скрытый UUID.

`age` и `birth_year` взаимоисключающие. Годы — астрономические годы календаря игры;
отрицательные допустимы. У старых полей правителей `birth_year: 0` всё ещё означает
«неизвестен»: конкретно этот год рождения данным срезом не поддерживается.
Очень большой возраст не даёт бессмертия: обычные правила смертности продолжают работать.

Министры задаются по ID реально объявленного портфеля, политика — по его `option`:

```yaml
effects:
  ministers:
    defense:
      name: Example Minister
      age: 48
      option: quartermaster_general
      portrait: my_uniform_portrait
```

**Проверьте ID** в своём `common/rulers`: `defense`/`quartermaster_general` существуют
в базовой игре; неизвестные портфели и опции диагностируются, не создаются автоматически.
Для назначения в пустой портфель нужна `option`. У действующего можно менять только
имя/черту/возраст/портрет. Политические бонусы министерства по-прежнему задаёт его
`option`; личная черта министра не превращается в отдельную систему бонусов.

`{dismiss: true}` снимает министра вместе с его политикой. Для главы государства
это запускает обычное преемство — нынешняя модель не оставляет кресло пустым.
`{death: true}` использует тот же путь преемства/смерти и хронику. Совмещать эти
операции с редактированием полей в одном объекте нельзя.

Операции над людьми выполняются после числовых эффектов. Между собой сохраняют
порядок объявления; `use` переносит и их из `common/scripted_effects`.
Ожидающий выбор события сохраняет эти операции, а не только числовые бонусы.
Сценарные эффекты — авторское изменение мира, не бесплатная обычная кнопка найма:
цену/условия своего решения моддер задаёт явно. UI-найм сохраняет прежние ограничения.

## Условия события

```yaml
trigger:
  officeholders:
    head_of_state:
      name: Example Leader
      trait: reformer
      portrait: my_civilian_portrait
      min_age: 40
      max_age: 60
```

Допустимы `head_of_state`, `head_of_government` и ID министерского портфеля.
Все заданные поля проверяются через AND. Пустой портфель/отсутствующий премьер не
считаются совпадением. Проверка ничего не назначает, не тратит деньги и не двигает RNG.
Неверный объект условия закрывается диагностикой, а не превращается в безусловный ивент.

## Что сохранено от прежнего устройства

`common/rulers` — офисы, личные черты, портфели/политики; `history/rulers` — исходные
лица; `common/character_names` — имена генерации; `gfx` — изображения;
`localization` — подписи. Не копируйте весь каталог ради одного портрета.
Новые портретные привязки переживают обычный сейв и сетевой снимок; пустые поля
старых сейвов остаются пустыми. Отпечаток кампании учитывает явную смену графики.
