# JSON + YAML для модов

Файлы данных можно писать в `.json`, `.yaml` и `.yml`, смешивая форматы в одном моде.
Структуры, названия ключей, проверки значений и правила частичного переопределения одинаковые.
Никакой компиляции YAML-моду не требуется. Старые JSON-моды продолжают работать.

## Где поддерживается

- Тематические каталоги `common/`: товары, здания, defines, units, programme, production,
  политика, модификаторы, ИИ, механики и остальные реально загружаемые категории.
- `events/`, структурированные библиотеки `scripted_triggers/` и `scripted_effects/` внутри `common/`.
- JSON-структуры истории стран, регионов, населения, армии и флота; их можно заменить YAML.
- `interface/`, `gui/`, `localization/`, `gfx/`, `fonts/`, `sound/`, `music/`.
- Структурированные определения карты, включая типы местности, `terrain_settings.yaml`
  или `.yml` и переопределения местности провинций.
- Новые `common/laws`, `common/agendas`, `common/national_courses`,
  `common/alliance_programs`, `map_data/water_settings` и частичные
  `map_data/source_tables.yaml/yml` с теми же проверками, что JSON.

Не означает поддержку произвольных новых папок: категория должна иметь загрузчик.
Расширение меняет способ чтения, а не добавляет несуществующую механику.

Манифесты модов и DLC (`manifest.json`, `dlc.json`), сценарные дескрипторы и `world.json`,
сохранения, настройки пользователя, сетевые сообщения и служебные кэши пока остаются JSON.
Исходные географические GeoJSON, политические CSV, PNG-карты и другие бинарные ресурсы
сохраняют свои форматы.

## Внутриигровой редактор

Редактор контента показывает `.json`, `.yaml` и `.yml`, включая `events/`. Можно
создать YAML-документ, проверить его, изменить через дерево свойств и сохранить
в свой `Editor workspace`. Схемы и поддерживаемые механики от расширения не меняются.
В заголовке видны путь документа и его формат; полный текст — на вкладке «Исходник».

Простое сохранение исходника не конвертирует YAML и сохраняет его комментарии.
Правка через дерево свойств или визуальный макет **переформатирует документ и
убирает комментарии** — это указано над редактором; Ctrl+Z возвращает прошлый текст.
Строки и ключи записываются в кавычках, поэтому `001`, `NO`, даты и цвета не превращаются
в другие типы. Целые и десятичные числа не проходят через `double` при конвертации.
Явно заключённый в кавычки ключ `"<<"` — обычная строка, не инструкция слияния.

Редактор пишет только в пакет пользователя, хранит `.bak` предыдущей версии и
отказывается перезаписывать файл, изменённый другим редактором после открытия.
Для связанных файлов API `ContentWorkbench.WriteBatch` принимает смешанные форматы
с общей проверкой и откатом. Ошибка YAML сообщает путь и позицию; ошибочная группа
не сохраняется частично. Проверка синтаксиса не заменяет все проверки игровых
каталогов: оставшиеся правила проверяются при загрузке, как и для JSON.

## Порядок переопределений

Как раньше: базовые данные → активные пакеты в их порядке загрузки → следующий файл
категории по имени. У JSON нет специального приоритета над YAML или наоборот.
Например `00_base.json`, `50_balance.yml`, `90_final.yaml` применяются именно в этом порядке.
Регистр расширения не важен; `.yaml.bak` и `.yml.tmp` не загружаются.
Для однозначного порядка используйте различные числовые префиксы. Два одноимённых
файла разных расширений — два отдельных переопределения, а не альтернативные копии.

В YAML можно делать тот же частичный overlay, что в JSON:

```yaml
# common/programme/50_my_units.yaml
units_per_factory: 12
conversion:
  efficiency: 0.5
lines:
  Steel:
    pool: civilian
```

Здесь остальные линии наследуются. Это настройки распределения мощностей, а не рецепт
выпуска: для нового товара отдельно объявите товар и производственный рецепт.

```yaml
# common/defines/50_early_scenario.yml
Features:
  aviation: false
  drones: false
```

Для сценарного включения используются существующие `FeatureUnlocks` и скриптовые
условия — см. [переключатели механик](MECHANIC_FEATURES_RU.md). YAML сам по себе не язык скриптов.

```yaml
# gfx/interface/50_icons.yaml
sprites:
  icon_good_steel:
    texture: icons/my_steel.png
    source_colour: "#e7bd69"
```

PNG остаётся отдельным редактируемым файлом. `source_colour` описывает цвет в самом PNG,
чтобы UI корректно применял палитру. Белой маске это поле не требуется.

## Синтаксис и защита от неоднозначностей

Поддерживаются комментарии `#`, словари, списки, вложенность, flow-формы `[a, b]` / `{a: b}`,
кавычки, Unicode, многострочный текст `|` и свёрнутый текст `>`.

- `true` / `false` — boolean, `null`, `~` и пустое значение — null.
- Decimal/exponent числа совместимы с JSON: `12`, `-3`, `0.5`, `1e-3`.
- `NO`, `on`, `off`, `yes`, `no`, даты и идентификаторы `001` остаются строками.
  Кавычки всегда оставляют значение строкой: `"true"` не boolean.
- Цвета с `#` обязательно в кавычках: `"#e7bd69"`. Иначе YAML видит комментарий.
  Для значения, похожего на число, но являющегося идентификатором, тоже используйте кавычки.
- Ключи словарей — scalar-строки; ID провинций допустимы, сложные ключи-коллекции нет.
- Повторяющиеся ключи в одном словаре дают ошибку. Для изменения значения используйте
  следующий файл overlay, а не повторение того же ключа.
- Допустимы стандартные `!!str`, `!!bool`, `!!int`, `!!float`, `!!null`, `!!map`, `!!seq`;
  числа и boolean при явном теге должны соответствовать правилам выше.
- Один документ на файл. Anchors `&`, aliases `*`, merge-key `<<`, custom tags,
  десериализация объектов .NET и исполняемые конструкции не поддерживаются.
- Лимиты YAML: 32 MiB входного текста, глубина до 64 уровней, до 1 000 000 узлов.

Ошибка синтаксиса сообщает имя файла и позицию парсера; такой файл пропускается,
а другие корректные файлы продолжают загружаться. UI/localization YAML перечитывается
тем же Ctrl+Shift+R. Баланс и стартовая история требуют новой кампании, как JSON.

Готовый отключённый пример: `mods/_templates/yaml-data/`.
Законы и органические повестки: [пример и игровые правила](GOVERNANCE_FINANCE_2026_10_06_RU.md).
Таблицы исходной географии требуют строковых ячеек, включая числовые ID:
[формат таблиц и миграция](SOURCE_MAP_MIGRATION_RU.md).
Проверка: `dotnet run --project Tools/FormableTests -- --yaml-only`.

Парсер: закреплённая версия [YamlDotNet 18.1.0](https://www.nuget.org/packages/YamlDotNet/18.1.0),
MIT. Общая зависимость задаётся в `Scripts/Simulation/StructuredData.Dependencies.props`;
тестовые инструменты используют тот же парсер, что игра.
