# Эпохи, здания и размещение

Определения зданий остаются в `game/common/buildings`, рецепты — в
`game/common/production`. Ограничения сценария задаются отдельно в
`game/common/building_rules/*.json`, `*.yaml` или `*.yml` внутри пакета мода.
Так античный мод не обязан менять C# ради отключения авиабазы или периода
доступности своего здания. Ядро не подставляет современную дату вместо даты сценария.

Пример YAML (те же ключи разрешены в JSON):

```yaml
AirBase:
  enabled: false
University:
  available_from: "1100-01-01"
  available_until: null
  requires_technologies: []
```

Ключ — ID здания из каталога, а не переведённая надпись. Даты включительны,
читаются HistoricalDate, в том числе астрономические отрицательные годы;
год 0 соответствует 1 году до н. э. Пропущенное свойство сохраняет предыдущее
правило, null у даты снимает её ограничение. Пустой список снимает требование
технологий. Все названные технологии должны быть изучены. Неверное правило
отвергается целиком, не стирая предыдущее корректное.

Сами новые здания и их рецепты по-прежнему надо объявить. Добавление правила
не создаёт здание или технологию. Ошибки доступны в BuildingRules.Problems;
полная интеграция этих ошибок в редактор/общий валидатор ещё открыта.

Каталог больше не ограничен запасом в 64 позиции производственной таблицы.
Проверено расширение на 200 зданий и 200 товаров с сохранением старых рецептов;
это не обещание неограниченной памяти на любом устройстве.

«На карте» использует ту же QueueConstructionCommand, что обычная очередь.
Щелчок выбирает регион, не отдельный участок. Проверяются владелец/действующее
управление, суша, берег для водных зданий, лимит проектов, начальный взнос,
эпоха и технологии. Длительность приблизительная: финансирование и темп стройки
могут измениться после постановки. Esc/правая кнопка закрывают инструмент.
