# Частота фоновых событий

Обычные случайные события для человеческих стран появляются раз в 125 игровых
дней вместо 75: за 3750 дней это 30 предложений вместо 50, на 40% меньше.
Новый запрос не создаётся, пока страна не ответила на предыдущий.

В `common/defines/*.json` мода или сценария доступны:

```json
{
  "EventIntervalDays": 125,
  "MovementEventIntervalDays": -1,
  "EventMemoryDays": 1460,
  "EventExpiryDays": 182
}
```

- `EventIntervalDays`: дни между фоновыми событиями стран. Ноль или отрицательное
  значение отключает только автоматическую выдачу фоновых карточек.
- `MovementEventIntervalDays`: отдельная частота для человеческих движений без
  земли. Отрицательное значение наследует общую частоту, ноль отключает,
  положительное задаёт свой интервал.
- `EventMemoryDays`: окно памяти для уменьшения веса недавно увиденных событий.
- `EventExpiryDays`: срок ответа на обычную фоновую карточку.

Сецессии, предложения объединения и явно вызванные скриптом события не исчезают
при отключении фоновых карточек. Уже ожидающие ответа запросы сохраняют срок
действия. Наблюдатель не получает фоновых окон; имеющиеся запросы разрешаются
автоматически. Авторские сценарии сохраняют свои правила в сейве. Базовый
сценарий 2024, как и раньше, загружает актуальные дефайны игры и активных модов:
новая частота действует также при загрузке его старого сохранения.

Проверка: `dotnet run --project Tools/FormableTests/FormableTests.csproj -c Release -- --events-only`.
Она охватывает частоту, нулевые интервалы, ожидание ответа, истечение срока,
наблюдателя, страны и движения в hotseat и сохранение настроек.
