# C# через код этой игры

Это не справочник по языку. Справочников по C# в интернете сотни, и все они учат языку
вообще — на консольных калькуляторах и классах `Animal`. Здесь другое: мы учим ровно тот

из `Scripts/`, а не выдумка ради примера.

Читать подряд. Каждый раздел заканчивается тем, что вы можете открыть файл, найти там
описанное и убедиться своими глазами.

**Что вам понадобится знать заранее:** ничего. Совсем. Если вы умеете открыть папку и
текстовый редактор — этого достаточно.

**Куда вы придёте:** в конце вы добавите в игру собственное поле в модель страны,
собственную команду, покажете их в интерфейсе и напишете к ним проверку, которая
сломается, если кто-то потом сломает вашу работу.

**Если C# вам не нужен вообще** — огромная часть игры настраивается JSON-файлами без

<a name="1-как-устроена-игра"></a>

## 1. Как устроена игра

Прежде чем первая строка C#, одна картинка. Без неё половина решений в коде выглядит
произволом.

Игра состоит из **двух половин**, и граница между ними — не условность, а правило,
которое компилятор проверяет за вас.

```
Scripts/Simulation/        ← симуляция. Про Godot не знает вообще.
    SimulationCore.cs          страна, кампания, календарь, случайность
    EconomyCore.cs, TradeCore.cs   экономика
    MilitaryCore.cs            армии и фронты
    PeaceConference.cs         мирные договоры
    CentralBank.cs             ставка и печатный станок
    ...

Scripts/ui/, Scripts/*.cs  ← интерфейс. Godot знает, правила — нет.
    DealOrForceGame.cs         корень кампании
    StateAffairsUI.cs          экран государства
    TradeInstructionsUI.cs     торговые указания
    ...
```

**Правило одно: в `Scripts/Simulation/` нет ни одного `using Godot;`.**

Зачем такая строгость:

- **Симуляцию можно запустить без игры.** В папке `Tools/SimBench` лежит отдельная
  программа, которая берёт те же самые файлы симуляции, прогоняет десятилетия за минуты
  и проверяет сотню утверждений о мире. Никакого окна, никакой видеокарты. Это возможно
  ровно потому, что симуляция не зависит от движка.
- **Правила нельзя случайно сломать кнопкой.** Если экономика умеет меняться только
  через команды (раздел 10), то не бывает такого, что одна кнопка втихую поменяла налог
  мимо всех проверок.
- **Мультиплеер и сохранения.** Два компьютера, прогнавшие одни и те же команды,
  обязаны получить один и тот же мир. Про это раздел 13.

Держите эту картинку в голове: **вопрос «а где это лежит?» почти всегда решается
вопросом «это правило игры или это экран?»**

<a name="2-инструменты-за-пять-минут"></a>

## 2. Инструменты за пять минут

Нужны две вещи: Godot 4.7 с поддержкой .NET (сборка «mono») и .NET SDK 8.

### Собрать игру

```bash
dotnet build DealOrForce.csproj -c Debug
```

`-c Debug` — это **конфигурация**. Их две, и путать их дорого:

| | `Debug` | `Release` |
|---|---|---|
| кто этим пользуется | редактор Godot, когда вы жмёте «играть» | `Tools/SimBench` и готовая сборка |
| проверки внутри | включены | выключены |
| скорость | медленнее | быстрее |
| куда кладёт файлы | своя папка | своя папка |

**Собрали не ту — получите не тот результат.** Редактор берёт `Debug`; если вы
пересобрали только `Release`, редактор продолжит запускать вчерашний код и вы будете
искать несуществующий баг.

### Прогнать проверки

```bash
dotnet run --project Tools/SimBench/SimBench.csproj -c Release
```

Это займёт десятки минут — она честно проживает годы игрового времени. В конце она
напишет, сколько проверок прошло и сколько нет. **Это ваша страховка:** если вы поменяли
формулу и мир после этого сложился, вы узнаете об этом здесь, а не от игрока.

### Посмотреть, что получилось

Запустите игру из редактора. Клавиша `~` открывает консоль разработчика; `help`
показывает все команды.

<a name="3-азбука"></a>

## 3. Азбука

### Переменная — это именованная коробка со значением

```csharp
int day = 0;
float stability = 0.65f;
string tag = "KOR";
bool atWar = false;
```

Слева — **тип**, потом имя, потом значение. Тип в C# обязателен и проверяется при
сборке: `int day = "понедельник";` не соберётся. Это не придирка компилятора, это он
ловит вашу ошибку сегодня, а не в бою.

### Типы чисел, которые здесь реально встречаются

| Тип | Что это | Где в игре |
|---|---|---|
| `int` | целое, примерно ±2 млрд | `Id`, номер дня, количество дивизий |
| `long` | целое, очень большое | население мира |
| `float` | дробное, 7 значащих цифр | доли, ставки, стабильность |
| `double` | дробное, 15 цифр | `delta` кадра в Godot |

**Суффикс `f` обязателен.** `0.65` — это `double`, а `0.65f` — `float`. Строка
`float x = 0.65;` не соберётся, и это правильно: язык не хочет молча терять точность за
вашей спиной.

### `var` — «выведи тип сам»

```csharp
var korea = campaign.NationByTag("KOR");
```

Тип у переменной всё равно есть и он всё равно проверяется — просто вы не пишете его
руками, когда он и так очевиден из правой части. В этом проекте `var` используется почти
везде, где тип читается из строки.

### Строки и интерполяция

```csharp
var line = $"{nation.DisplayName} · {nation.Stability:P0}";
```

Доллар перед кавычкой включает **интерполяцию**: всё в фигурных скобках вычисляется и
подставляется. После двоеточия — формат:

- `:P0` — проценты без дробной части: `0.744` → `74%`
- `:N0` — число с разделителями разрядов: `51700000` → `51 700 000`
- `:0.##` — до двух знаков, лишние нули не рисовать: `2.25` → `2,25`

**Важно:** так можно склеивать числа, но **нельзя склеивать переводимый текст**. Почему —
в разделе 15.

<a name="4-класс-и-объект"></a>

## 4. Класс и объект

Откройте `Scripts/Simulation/SimulationCore.cs` и найдите строку 145:

```csharp
public sealed partial class Nation
{
    public int Id;
    public string Tag = "";
    public string Name = "";
    public string Continent = "";
    public float StabilityBias;
    ...
}
```

Разбираем по словам, слева направо.

**`class`** — описание типа. Не сама страна, а чертёж страны: какие у неё вообще бывают
поля. Конкретная Южная Корея — это **объект** (ещё говорят «экземпляр»), и таких объектов
в кампании двести с лишним.

**`public`** — этот член виден отовсюду. Есть ещё `private` (только внутри этого класса) и
`internal` (только внутри этой сборки). По умолчанию, если не написать ничего, будет
`private` — самое закрытое.

**`sealed`** — от этого класса нельзя наследоваться. В этой игре так почти везде:
наследование добавляет вопрос «а какая именно страна тут на самом деле?», а модель данных,
которую надо сохранять в файл и сверять между двумя компьютерами, от таких вопросов
только страдает.

**`partial`** — и вот это интересно. `Nation` описан не в одном файле:

```
Scripts/Simulation/SimulationCore.cs:145   public sealed partial class Nation
Scripts/Simulation/TradeCore.cs:32         public sealed partial class Nation
Scripts/Simulation/Statecraft.cs:29        public sealed partial class Nation
Scripts/Simulation/Attrition.cs:6          public sealed partial class Nation
Scripts/Simulation/AiJudgement.cs:7        public sealed partial class Nation
```

Это **один и тот же класс**, просто разложенный по темам: то, что страна знает о торговле,
лежит рядом с торговлей, а не в общей куче. Компилятор склеивает их обратно в один тип.
Страна от этого не раздваивается — объект по-прежнему один.

**Поле со значением по умолчанию.** `public string Tag = "";` — если никто не задаст тег,
он будет пустой строкой, а не `null`. Разница огромная: у пустой строки можно спросить
длину, у `null` — нельзя (раздел 6). Это маленькая привычка, которая убирает целый класс
падений.

### Создать объект

```csharp
var nation = new Nation { Tag = "KOR", Name = "South Korea" };
```

`new` создаёт, фигурные скобки сразу заполняют поля. В игре страны обычно не создают
руками — их строит сценарий из JSON, — но синтаксис вы увидите постоянно.

<a name="5-методы-и-свойства"></a>

## 5. Методы и свойства

### Метод — это действие с именем

```csharp
public static string Of(string tag)
{
    if (string.IsNullOrEmpty(tag)) return "";
    ...
    return Loc.Has($"country.{tag}.name") ? Loc.Get($"country.{tag}.name") : tag;
}
```

(`Scripts/Simulation/CountryNames.cs`)

Читаем: `public` — виден всем. `static` — принадлежит **типу**, а не конкретному объекту:
вызывается как `CountryNames.Of("KOR")`, никакой отдельной «страны имён» для этого
создавать не надо. `string` — что метод возвращает. `Of` — имя. `(string tag)` —
параметр.

`return` заканчивает метод здесь же. В примере два `return` — и это нормально и хорошо:
ранний выход на плохом входе избавляет от вложенных `if` на всё остальное тело.

**Тернарный оператор** `условие ? это : иначе_это` — короткая форма `if`, годная тогда,
когда обе ветки — одно выражение.

### Свойство — поле, за которым стоит вычисление

```csharp
public string DisplayName => CountryNames.Resolve(this, false);
```

Снаружи это читается как поле — `nation.DisplayName`, — но значения нигде не хранится, оно
считается в момент обращения. Стрелка `=>` значит «это свойство равно вот этому
выражению».

Почему `Name` — поле, а `DisplayName` — свойство, и почему это не придирка: `Name` — то,
как страна названа в данных, и это значение уезжает в файл сохранения, в логи и в
проверки, где оно обязано быть одинаковым при любом языке интерфейса. `DisplayName` — то
же имя, но пропущенное через таблицу перевода игрока. Одно хранится, второе выводится.
**Если вы когда-нибудь увидите в сохранении русское название страны — сломалось именно
это разделение.**

### `this`

`this` внутри метода — «тот самый объект, у которого метод вызвали». В `Resolve(this,
false)` страна передаёт саму себя.

<a name="6-null"></a>

## 6. `null`

`null` — это «ссылки нет». Не пустая строка, не ноль — именно отсутствие объекта.
Обращение к члену `null` роняет программу с `NullReferenceException`, и это **самая
частая ошибка** в чужом коде, который вы будете править.

Возникает он обычно из поиска, который ничего не нашёл:

```csharp
var nation = campaign.NationByTag("XXX");   // такой страны нет → null
var stability = nation.Stability;            // ← падение здесь
```

### Четыре инструмента, которыми это лечится

**1. Проверить и выйти.** Так написано почти всё в этом проекте:

```csharp
public void Apply(Campaign campaign)
{
    var nation = campaign?.NationById(IssuerId);
    if (nation is null) return;
    CentralBank.SetEmission(nation, ShareOfOutput);
}
```

(`Scripts/Simulation/CentralBank.cs`, `SetEmissionCommand`)

`is null` читается ровно как звучит. Есть и `is not null`.

**2. `?.` — «а если null, то и не надо».**

```csharp
var nation = campaign?.NationById(IssuerId);
```

Если `campaign` — `null`, то вызов не делается вовсе и всё выражение становится `null`.
Цепочка обрывается тихо вместо падения.

**3. `??` — запасное значение.**

```csharp
public int Day => Campaign?.ElapsedDays ?? 0;
```

«День кампании, а если кампании нет — ноль».

**4. `= null!` — «я знаю, что здесь будет значение».**

```csharp
private Label _pickerSubheading = null!;
```

Восклицательный знак — обещание компилятору: «не ругайся, я присвою это в `_Ready` до
первого использования». Обещание ничем не подкреплено, поэтому так пишут только про поля
интерфейса, которые заполняются при построении экрана.

<a name="7-коллекции"></a>

## 7. Коллекции

### `List<T>` — список

```csharp
List<Army> armies = campaign.Armies;
armies.Add(newArmy);
var first = armies[0];
var count = armies.Count;
```

`<T>` — тип элементов. `List<Army>` — список армий, `List<string>` — список строк.
Порядок сохраняется, элементы можно добавлять и удалять.

### `Dictionary<K, V>` — словарь, поиск по ключу

```csharp
public readonly Dictionary<string, float> TradeSettings = new(StringComparer.Ordinal);
```

Ключ → значение. Главное свойство: найти по ключу — мгновенно, сколько бы там ни было
записей. Именно поэтому торговые указания хранятся так: `good/Food/import_priority` →
`2.25`.

Доставать оттуда надо **аккуратно**:

```csharp
// упадёт, если ключа нет:
var value = nation.TradeSettings[key];

// правильно:
if (nation.TradeSettings.TryGetValue(key, out var value))
    ...
```

`out var value` — «заведи тут переменную и положи в неё результат». Метод возвращает
`true`/`false`, нашёл или нет.

### `HashSet<T>` — множество

```csharp
public readonly HashSet<string> Delegated = new(StringComparer.Ordinal);
```

Просто набор: элемент либо есть, либо нет, повторов не бывает. `Add` возвращает `true`,
если элемент действительно добавился, и `false`, если он уже был, — и на этом построен
весь механизм «не докладывать об одной и той же проблеме дважды» в
`Scripts/ui/LayoutAudit.cs`.

### `StringComparer.Ordinal` — зачем он в каждой второй коллекции

Это указание сравнивать строки **по кодам символов, тупо и одинаково везде**. Без него
.NET сравнивает по правилам текущего языка операционной системы — и словарь, собранный на
турецкой Windows, может повести себя не так, как на русской, потому что в турецком языке
буква `i` приводится к верхнему регистру иначе. Для мира, который обязан совпасть на двух
компьютерах, это неприемлемо. Поэтому: **любая коллекция со строковыми ключами в
симуляции — `Ordinal`.**

### Ловушка: не менять коллекцию, по которой идёшь

```csharp
foreach (var army in campaign.Armies)
    if (army.Strength <= 0) campaign.Armies.Remove(army);   // ← исключение
```

Соберите сначала, удалите потом:

```csharp
var dead = campaign.Armies.Where(army => army.Strength <= 0).ToList();
foreach (var army in dead) campaign.Armies.Remove(army);
```

`ToList()` здесь обязателен: без него `dead` — это не список, а «инструкция, как его
получить», и она выполнится во время удаления, то есть в тот самый неподходящий момент.

<a name="8-linq"></a>

## 8. LINQ

LINQ — набор методов для запросов к коллекциям. Читается почти как предложение.

```csharp
var worstGood = player.Market.Values
    .OrderBy(quote => quote.Satisfaction)
    .FirstOrDefault();
```

(`Scripts/ui/StrategicHudUI.cs` — тот самый товар, который попадает в сводку справа)

Стрелка `=>` здесь — **лямбда**, безымянная функция: «дай мне `quote`, я верну тебе
`quote.Satisfaction`». `OrderBy` сортирует по этому значению, `FirstOrDefault` берёт
первый — или `null`, если список пуст (`...OrDefault` во всех этих методах значит ровно
это: «а если нечего — верни пустое место, не падай»).

Что стоит знать в лицо:

| Метод | Что делает |
|---|---|
| `Where(x => ...)` | оставить подходящие |
| `Select(x => ...)` | превратить каждый во что-то другое |
| `OrderBy` / `OrderByDescending` | отсортировать |
| `FirstOrDefault` | первый или `null` |
| `Any(x => ...)` | «есть ли хоть один такой» |
| `All(x => ...)` | «все ли такие» |
| `Sum`, `Count`, `Max`, `Min` | сумма, количество, максимум, минимум |
| `ToList()`, `ToArray()` | зафиксировать результат |

### Когда LINQ не надо

LINQ создаёт объекты. Один запрос — пустяк. Но код симуляции выполняется **для каждой
страны каждый игровой час**, и там запрос внутри запроса превращается в миллионы
временных объектов в секунду, сборщик мусора начинает просыпаться, и игра дёргается.

Правило этого проекта простое: **в интерфейсе и в редких событиях — LINQ, он честнее
читается. В горячем цикле симуляции — обычный `for`/`foreach` и заранее выделенный
буфер.** Если сомневаетесь — посмотрите, как написано рядом.

<a name="9-enum-и-switch"></a>

## 9. `enum` и `switch`

`enum` — тип, у которого конечный список значений с именами:

```csharp
public enum Fault
{
    Squeezed,
    Clipped
}
```

(`Scripts/ui/LayoutAudit.cs`)

Зачем, если можно строкой или числом: компилятор не даст написать `Fault.Squished` с
опечаткой, а редактор подскажет список. Ошибка ловится при сборке, а не глазами.

### `switch` как выражение

```csharp
public static string CategorySource(string category) => category.ToLowerInvariant() switch
{
    "game"      => "Game",
    "interface" => "Interface",
    "video"     => "Display",
    "audio"     => "Sound",
    _           => category
};
```

(`Scripts/ui/SettingsRows.cs`)

Читается сверху вниз: совпало — вернулось. `_` — «всё остальное». Это **выражение**: оно
возвращает значение, поэтому весь метод умещается в одну стрелку.

### Сопоставление с образцом

C# умеет проверять тип и форму объекта прямо в условии, и в этом коде это встречается
постоянно:

```csharp
if (node is Control { Visible: false }) return;
```

Читается: «если `node` — это `Control`, и при этом его `Visible` равен `false`».

```csharp
if (node is Label label && !string.IsNullOrWhiteSpace(label.Text))
```

«Если это `Label` — заодно назови его `label` — и его текст не пустой».

```csharp
return label.HorizontalAlignment is HorizontalAlignment.Right or HorizontalAlignment.Center;
```

`or` внутри образца — «или то, или это».

<a name="10-интерфейсы-и-команды"></a>

## 10. Интерфейсы и команды

**Интерфейс** — это список того, что тип обязан уметь, без единой строчки о том, как.

```csharp
public interface ICampaignCommand
{
    int IssuerId { get; }
    void Apply(Campaign campaign);
}
```

(`Scripts/Simulation/SimulationCore.cs`)

Любой тип, который заявит `: ICampaignCommand`, обязан иметь `IssuerId` и `Apply`.
Взамен его можно положить в очередь команд, ничего не зная о том, что он такое.

### Настоящая команда целиком

```csharp
public sealed class SetEmissionCommand : ICampaignCommand
{
    public int IssuerId { get; init; }

    /// <summary>Доля годового выпуска в год. 0.05 — пять процентов ВВП в год.</summary>
    public float ShareOfOutput { get; init; }

    public void Apply(Campaign campaign)
    {
        var nation = campaign?.NationById(IssuerId);
        if (nation is null) return;
        CentralBank.SetEmission(nation, ShareOfOutput);
    }
}
```

(`Scripts/Simulation/CentralBank.cs`)

`{ get; init; }` — свойство, которое можно задать **только при создании** и нельзя
поменять после. Команда — это записка о намерении; записка, которую можно переписать по
дороге, бесполезна.

### Зачем вообще команды

Кнопка не трогает мир. Она пишет записку:

```
Кнопка  →  new SetEmissionCommand { IssuerId = ..., ShareOfOutput = ... }
        →  campaign.Commands.Enqueue(команда)
        →  campaign.Commands.ApplyAll(campaign)
        →  Apply(campaign) меняет мир
        →  интерфейс перерисовывается
```

Что это даёт, по пунктам:

- **Мультиплеер.** По сети летит записка, а не изменённый мир. Два клиента применяют
  одинаковые записки в одинаковом порядке и получают одинаковый мир.
- **Права.** `IssuerId` — кто это просит. Игрок не может подписать договор за чужую
  страну, потому что в записке написано, кто её написал.
- **Проверяемость.** Проверка в `SimBench` создаёт команду и применяет её без всякого
  интерфейса. Если бы кнопка меняла поле напрямую, проверить это без нажатия кнопки было
  бы невозможно.
- **Отказ — тоже ответ.** Посмотрите на `SetKeyRateCommand` рядом: у него есть
  `Accepted` и `Applied`. Команда может сказать «нет, центробанк независим» — и интерфейс
  узнает об этом честно, а не показав игроку значение, которого в мире нет.

**Правило:** если ваше изменение мира должно быть видно в мультиплеере, в сохранении или
в проверке — это команда. Если это «раскрыть панель» — это не команда, это интерфейс.

<a name="11-struct-и-record"></a>

## 11. `struct` и `record`

`class` — ссылка: переменная указывает на объект, и две переменные могут указывать на
один и тот же. `struct` — значение: оно копируется целиком при присваивании.

```csharp
public struct GameDate
{
    public int Year;
    public int Month;
    public int Day;
    public int Hour;
    ...
}
```

(`Scripts/Simulation/SimulationCore.cs`)

Дата — это значение, как число. Никому не нужно «ссылаться на ту самую дату»; нужно её
скопировать и посчитать. Поэтому `struct`.

### `record struct` — значение, которое само умеет себя сравнивать

```csharp
public readonly record struct Finding(string Path, string Text, float Width, float Height,
    Fault Fault, float Wanted);
```

(`Scripts/ui/LayoutAudit.cs`)

Одна строка, а получилось: шесть свойств, конструктор, сравнение «по содержимому» и
человекочитаемый вывод. `readonly` — после создания не меняется.

Это идеальная форма для «результата»: находка аудита, строчка отчёта, пара значений.
Когда вам нужно вернуть из метода три числа и подпись — не заводите класс, напишите
`record struct` в одну строку.

<a name="12-каталоги-данных"></a>

## 12. Каталоги данных

Это **главный паттерн игры**. Он объясняет, почему почти всё в ней можно поменять
JSON-файлом, и если вы поймёте только его одного — вы уже сможете добавлять содержимое.

Устроен любой каталог одинаково:

```csharp
public static class CommodityCatalog
{
    static CommodityCatalog() => ResetCatalog();

    public static void ResetCatalog(List<string> errors = null)
    {
        // 1. вернуть всё к встроенным значениям
        // 2. прочитать game/common/<папка>/*.json по порядку имён
        // 3. для каждого файла вызвать Merge
    }

    private static void Merge(JsonElement root)
    {
        // наложить прочитанное поверх того, что уже есть
    }
}
```

Три вещи, которые надо понять:

**`static class`** — у этого типа нет объектов вообще. Каталог товаров в мире один, его
не создают — к нему обращаются: `CommodityCatalog.Get(good)`.

**`static CommodityCatalog()`** — статический конструктор. Выполняется **один раз**, сам,
перед первым обращением к типу. Никто его не вызывает; .NET гарантирует, что он отработал
раньше, чем кто-либо успел спросить у каталога хоть что-то. Отсюда правило: каталог
всегда готов к моменту использования, и не бывает «а данные ещё не загрузились».

**`Merge`, а не «прочитать»** — файлы накладываются друг на друга **в порядке имён**, и
поздний переопределяет ранний по совпавшим ключам. Отсюда:

- файлы называют `00_base.json`, `10_...`, `90_...` — номер и есть очередь;
- мод не заменяет базовый файл, а **дополняет** его: чтобы поменять одно число, достаточно
  положить файл с одним числом;
- `ResetCatalog` начинается со сброса, поэтому перезагрузка модов — это просто повторный
  вызов, а не перезапуск игры.

Данные приходят из `GameDataLoader.DataDocuments("common", "<папка>")` — он и собирает
список файлов из игры и из всех включённых модов в правильном порядке.

**`List<string> errors`** — сюда каталог складывает жалобы на кривые данные вместо того,
чтобы упасть. Мод с опечаткой должен дать понятное сообщение, а не чёрный экран.

<a name="13-детерминизм"></a>

## 13. Детерминизм

Требование: **два прогона одних и тех же команд из одного зерна обязаны дать один и тот
же мир.** На этом держатся сохранения, повторы и мультиплеер. Нарушить его легко и
незаметно.

### Случайность

```csharp
public float NextFloat();
public int Range(int min, int max);
public bool Chance(float chance);
```

(`SimRandom` в `Scripts/Simulation/SimulationCore.cs`; живёт как `campaign.Random`)

**Никогда не пишите `new Random()` внутри правил.** Он берёт зерно из системного времени
— значит, у двух игроков разное, и миры разъедутся. `campaign.Random` хранит своё
состояние внутри кампании, оно попадает в сохранение (`RandomState` в `SaveSystem.cs`) и
воспроизводится точно.

```csharp
if (campaign.Random.Chance(0.05f)) { ... }          // правильно
if (new Random().NextDouble() < 0.05) { ... }        // так вы сломали мультиплеер
```

### Порядок перебора

`Dictionary` **не обещает порядок**. Если вы пройдёте по словарю и от порядка что-то
зависит — два прогона могут разойтись. Поэтому в коде постоянно встречается:

```csharp
foreach (var (key, value) in nation.TradeSettings.OrderBy(entry => entry.Key, StringComparer.Ordinal))
```

(`Scripts/ui/TradeInstructionsUI.cs`)

Отсортировали явно и по заданному правилу — получили один и тот же порядок везде.

### Дробные числа

`float` — приближение. `0.1f + 0.2f` не равно ровно `0.3f`. Поэтому:

```csharp
if (value == definition.Default) ...                       // ненадёжно
if (MathF.Abs(value - definition.Default) < 0.0001f) ...    // так и пишут в этом коде
```

Сравнивать дробные на равенство — сравнивать «достаточно ли они близки».

### Ещё три правила

- **Никакого времени системы** в правилах. `DateTime.Now` — только для интерфейса
  (например, год в копирайте).
- **Никакого ввода-вывода** в ежедневном цикле: файл или сеть посреди хода — это и
  тормоза, и недетерминизм.
- **Никакого обращения к Godot.** Симуляция не знает, есть ли вообще экран.

<a name="14-половина-на-godot"></a>

## 14. Половина на Godot

```csharp
public partial class DealOrForceGame : Control
{
    public override void _Ready() { ... }
    public override void _Process(double delta) { ... }
}
```

**`: Control`** — наследование: наш класс **является** узлом Godot и получает всё, что
узел умеет.

**`partial` здесь обязателен** — не для порядка, а технически: Godot генерирует для
каждого класса-узла вторую половину сама.

**`override`** — мы подменяем метод, который Godot вызывает сам:

- `_Ready()` — один раз, когда узел появился в сцене;
- `_Process(double delta)` — каждый кадр; `delta` — сколько секунд прошло с прошлого.

### Кадры — это не игровые дни

Самая важная мысль этой главы. Кадров в секунду может быть 30, может 144, может 7 на
слабой машине. **Если привязать игровое время к кадрам, на быстром компьютере игра пойдёт
быстрее.** Поэтому `_Process` копит `delta` и отдельно решает, пора ли делать шаг
симуляции:

```csharp
_dayAccumulator += delta;
var secondsPerDay = _campaign.Defines.SecondsForSpeed(_speed) * _campaign.TickScale;
while (_dayAccumulator >= secondsPerDay && ...)
{
    _dayAccumulator -= secondsPerDay;
    _campaign.Tick();
}
```

Обратите внимание на `&& ...`: там ещё условие про бюджет кадра. Кадру отводится
несколько миллисекунд на симуляцию, и если время вышло — цикл останавливается, а
оставшееся доделается в следующем кадре. Так медленная машина получает **медленную игру
вместо неотзывчивой**.

### Сигналы и лямбды

```csharp
button.Pressed += () => ShowSettingsCategory(category);
```

`+=` — подписка на событие. `() => ...` — лямбда без параметров.

**И вот ловушка, на которой спотыкаются все.** Лямбда **захватывает переменную, а не её
значение**:

```csharp
foreach (var category in SettingsCatalog.Categories())
{
    var captured = category;                                   // ← вот зачем эта строка
    var tab = new Button { Text = ... };
    tab.Pressed += () => ShowSettingsCategory(captured);
}
```

(`Scripts/MainMenuScene.cs`)

Если бы в лямбде стояло `category`, все кнопки в итоге открывали бы **последнюю**
категорию: цикл закончился, переменная осталась одна, и все лямбды смотрят в неё. Копия
`captured` — своя на каждый виток.

### Ловушка вёрстки, которая стоила пяти багов

Здесь это стоит знать наизусть, потому что оно выглядит не как баг:

```csharp
// НЕПРАВИЛЬНО — подпись схлопнется в ноль пикселей:
var caption = Fixed(Title("ABOUT ONE GOOD", 12, ...));
var value   = Fixed(Title("", 11, ...));
value.SizeFlagsHorizontal = SizeFlags.ExpandFill;

// ПРАВИЛЬНО — растягивается подпись, у значения фиксированная ширина:
var caption = Fixed(Title("ABOUT ONE GOOD", 12, ...));
caption.SizeFlagsHorizontal = SizeFlags.ExpandFill;
var value = Fixed(Title("", 11, ...), 120);
value.HorizontalAlignment = HorizontalAlignment.Right;
```

`Fixed(...)` включает обрезку текста и не задаёт минимальную ширину. Сосед с `ExpandFill`
забирает всё место, подпись получает ноль и **обрезает себя в точку**. На экране это
выглядит не как сломанная вёрстка, а как непонятная дизайнерская точка — поэтому четыре
раза подряд этого никто не замечал.

В игре есть сторож: `Scripts/ui/LayoutAudit.cs`. В отладочной сборке он раз в секунду
осматривает то, что на экране, и кричит в лог о подписи, которой не хватило места; команда
консоли `layout` спрашивает то же самое вручную.

<a name="15-локализация"></a>

## 15. Локализация

**Ключ перевода — это сама английская строка.**

```csharp
_governmentSetsRate.Text = Tr("The government controls the central bank");
```

И где-то в `game/localization/russian/*.json`:

```json
{ "The government controls the central bank": "Центробанк управляется правительством" }
```

Плюс: код читается без словаря. Минус, и он суровый: **изменили строку в коде — сломали
перевод**, потому что ключа с новым текстом в таблице нет и на экран вернётся английский.
Менять текст и таблицы надо **одним движением**, иначе русский экран однажды заговорит
по-английски.

### Что нельзя делать никогда

```csharp
// НЕЛЬЗЯ:
var line = Tr("Price") + ": " + Fmt.Money(price);
```

В другом языке порядок слов может быть другим, а переводчику достанется огрызок без
контекста. Надо так:

```csharp
Simulation.Loc.Format("Price {0}", Fmt.Money(price))
```

Вся фраза — один ключ, числа подставляются в `{0}`, `{1}`.

### Три функции

| | что делает |
|---|---|
| `Tr("...")` | перевести строку (в классах интерфейса) |
| `Loc.Format("... {0} ...", x)` | перевести и подставить |
| `Loc.Has("ключ")` | есть ли такой перевод вообще |

`Loc.Has` нужен там, где ключ собирается из данных: `country.KOR.name.belorussia` может
существовать, а может и нет, и «нет» — это нормальный ответ, а не ошибка.

### Именованные сущности — исключение

У стран, регионов, товаров ключ не английская строка, а идентификатор:
`country.KOR.name`, `region.1234.name`. Потому что имя страны — это данные, а не текст
интерфейса, и мод должен уметь добавить страну, которой в английской таблице нет вообще.

### Файлы

```
game/localization/english/00_english.json
game/localization/english/23_naming.json
game/localization/russian/00_russian.json
game/localization/russian/23_naming.json
```

Сливаются по порядку имён, поздний переопределяет раннего — ровно как каталоги данных из
раздела 12. Добавляя строки, заводите **новый пронумерованный файл**, а не правьте общий:
так ваши строки видно отдельно и конфликтов меньше.

<a name="16-практика-1"></a>

## 16. Практика 1: своё поле у страны, от модели до экрана

Задача: у страны появляется «настроение прессы» — число от 0 до 1, которое медленно
ползёт к стабильности. И его видно на экране государства.

### Шаг 1. Поле в модели

`Scripts/Simulation/SimulationCore.cs`, внутри `public sealed partial class Nation`:

```csharp
/// <summary>
/// Как о правительстве пишут. Ползёт к стабильности, но медленно: газеты меняют тон
/// позже, чем меняются обстоятельства.
/// </summary>
public float PressMood = 0.5f;
```

**Почему со значением по умолчанию:** старые сохранения про это поле ничего не знают. При
загрузке они его не заполнят, и оно останется `0.5f` — то есть старая кампания откроется и
будет вести себя разумно. Поле без значения по умолчанию превратило бы каждое старое
сохранение в страну с нулевым настроением прессы.

### Шаг 2. Правило, которое его двигает

В файл, где живёт стабильность (`Scripts/Simulation/StabilityCore.cs`), в ежедневный ход:

```csharp
// Десятая часть разрыва в день: за пару недель газеты догоняют реальность.
nation.PressMood += (nation.Stability - nation.PressMood) * 0.1f;
nation.PressMood = Math.Clamp(nation.PressMood, 0f, 1f);
```

`Math.Clamp(значение, минимум, максимум)` удерживает число в границах. Без него одна
кривая формула однажды выдаст `-3` и всё, что это число читает, начнёт врать.

### Шаг 3. Сохранение

Найдите в `Scripts/Simulation/SaveSystem.cs`, как сохраняются соседние поля страны, и
добавьте своё рядом — и в запись, и в чтение. **Поле, которое не сохраняется, обнуляется
при загрузке**, и это выглядит как «баг, который случается только после загрузки».

### Шаг 4. Показать

`Scripts/ui/StateAffairsUI.cs`, рядом с соседними строчками:

```csharp
rows.AddChild(Reading(Tr("Press mood"), $"{nation.PressMood:P0}"));
```

Точный помощник посмотрите в файле — там есть готовая форма строки «подпись — значение»,
и **используйте именно её**, а не собирайте руками: в ней уже учтена ловушка из раздела 14.

### Шаг 5. Перевод

Заведите `game/localization/english/31_press.json`:

```json
{ "Press mood": "Press mood" }
```

и `game/localization/russian/31_press.json`:

```json
{ "Press mood": "Настроение прессы" }
```

Английский файл нужен обязательно, даже что «ключ равен значению»: он — список того, что
вообще подлежит переводу.

### Шаг 6. Убедиться

```bash
dotnet build DealOrForce.csproj -c Debug
```

Запустите, откройте экран государства, найдите строку. Потом переключите язык и найдите
её ещё раз.

<a name="17-практика-2"></a>

## 17. Практика 2: своя команда

Задача: правительство может **надавить на прессу** — разово поднять настроение, заплатив
стабильностью.

### Команда

В `Scripts/Simulation/StabilityCore.cs` (или в своём файле рядом):

```csharp
/// <summary>
/// Приструнить газеты. Настроение прессы растёт сразу, стабильность падает: это видно
/// всем, и «всем» включает тех, кто это читает.
/// </summary>
public sealed class LeanOnThePressCommand : ICampaignCommand
{
    public int IssuerId { get; init; }

    /// <summary>Насколько надавили, 0..1. Больше — заметнее и дороже.</summary>
    public float Pressure { get; init; }

    public void Apply(Campaign campaign)
    {
        var nation = campaign?.NationById(IssuerId);
        if (nation is null) return;

        var pressure = Math.Clamp(Pressure, 0f, 1f);
        nation.PressMood = Math.Clamp(nation.PressMood + pressure * 0.25f, 0f, 1f);
        nation.Stability = Math.Clamp(nation.Stability - pressure * 0.05f, 0f, 1f);
    }
}
```

Обратите внимание: **команда ничего не считает про интерфейс и ничего про него не знает**.
Ей дали намерение и она его исполнила.

### Кнопка

В `Scripts/ui/StateAffairsUI.cs`:

```csharp
rows.AddChild(ActionButton(Tr("Lean on the press"), () =>
{
    _campaign.Commands.Enqueue(new LeanOnThePressCommand
    {
        IssuerId = _campaign.Player.Id,
        Pressure = 0.5f
    });
    _campaign.Commands.ApplyAll(_campaign);
    RefreshStateAffairs();
}, 160, 30));
```

Три строки по очереди: положили записку в очередь, попросили очередь примениться,
перерисовали экран. **Кнопка не трогает `nation.PressMood` напрямую** — и именно поэтому
это будет работать в мультиплеере и это можно будет проверить без кнопки. Что мы сейчас и
сделаем.

<a name="18-практика-3"></a>

## 18. Практика 3: своя проверка в SimBench

Проверка — это метод, который возвращает **пустую строку, если всё хорошо**, и текст
жалобы, если плохо. Откройте `Tools/SimBench/Program.cs` и посмотрите на соседей: они все
устроены одинаково.

```csharp
/// <summary>
/// Давление на прессу стоит ровно того, что обещано.
///
/// Три утверждения, и третье — то, ради чего проверка вообще пишется: границы. Формула,
/// которая ведёт себя правильно в середине и вылезает за 1 на краю, ломается не сразу,
/// а через десять лет игры, и искать её будут не там.
/// </summary>
private static string LeaningOnThePressCostsWhatItSays()
{
    var campaign = Campaign.CreateBootstrap(20250704);
    var nation = campaign.Nations.FirstOrDefault(country => country.Gdp > 100f);
    if (nation is null) return "не нашлось страны с экономикой";

    nation.PressMood = 0.40f;
    nation.Stability = 0.60f;

    new LeanOnThePressCommand { IssuerId = nation.Id, Pressure = 0.5f }.Apply(campaign);

    if (nation.PressMood <= 0.40f)
        return $"надавили, а настроение прессы осталось {nation.PressMood:P0}";
    if (nation.Stability >= 0.60f)
        return $"надавили бесплатно: стабильность осталась {nation.Stability:P0}";

    // И край: сколько ни дави, из отрезка 0..1 выходить нельзя.
    nation.PressMood = 0.99f;
    for (var attempt = 0; attempt < 20; attempt++)
        new LeanOnThePressCommand { IssuerId = nation.Id, Pressure = 1f }.Apply(campaign);
    if (nation.PressMood > 1f || nation.Stability < 0f)
        return $"границы не удержались: пресса {nation.PressMood}, стабильность {nation.Stability}";

    Console.WriteLine($"  пресса: {nation.Tag} надавил и получил {nation.PressMood:P0} " +
                      $"настроения за {nation.Stability:P0} стабильности.");
    return "";
}
```

И зарегистрировать рядом с остальными:

```csharp
failures += Check("давление на прессу стоит того, что обещано",
    LeaningOnThePressCostsWhatItSays());
```

Запустить:

```bash
dotnet run --project Tools/SimBench/SimBench.csproj -c Release
```

**Почему это стоит времени.** Проверка переживёт вас: через полгода кто-то оптимизирует
формулу стабильности и случайно уберёт `Clamp`. Без проверки это выяснится, когда у игрока
на десятом году появится страна со стабильностью −340 %. С проверкой — через сорок минут
после правки, с готовым описанием, что именно сломалось.

Обратите внимание и на строчку `Console.WriteLine`: **успешная проверка тоже что-то
рассказывает**. Не «ок», а числа, по которым видно, что мир вообще похож на мир.

## 19. Как читать чужой код этой игры

Три приёма, которые экономят часы.

**1. Ищите по тексту с экрана.** Увидели на экране слово — оно же и ключ перевода, и оно
же есть в коде:

```bash
grep -rn "The government controls the central bank" Scripts/
```

Так вы попадаете точно в нужный файл, минуя догадки.

**2. Читайте комментарии — в этом проекте они объясняют «почему».** Комментарий вида
«четыре раза подряд эта подпись схлопывалась» стоит десяти минут разглядывания кода.
Комментарии `/// <summary>` над классом — это не формальность, а самое короткое описание
того, зачем эта вещь вообще есть.

**3. Идите за именем.** Нашли `CentralBank.SetEmission` — откройте `CentralBank.cs` и
прочтите весь класс целиком, он небольшой. В этом проекте один файл — одна тема, и почти
всегда полезнее прочитать файл, чем выковыривать одну функцию.

<a name="20-ошибки"></a>

## 20. Ошибки, которые вы совершите

| Что вы увидите | Что случилось | Что делать |
|---|---|---|
| `NullReferenceException` | обратились к тому, чего нет | `if (x is null) return;` перед обращением; см. раздел 6 |
| `Collection was modified` | меняли коллекцию внутри `foreach` по ней | сначала `.ToList()`, потом менять |
| число получилось `0`, хотя не должно | целочисленное деление: `1 / 2` это `0` | `1f / 2f` |
| условие не срабатывает на «ровном» числе | сравнили `float` на равенство | `MathF.Abs(a - b) < 0.0001f` |
| на русском экране английская фраза | забыли `Tr`, или поменяли строку и не поменяли таблицу | найти ключ, поправить **все** файлы разом |
| подпись превратилась в точку | ловушка `Fixed(Title(...))` | раздел 14; проверить командой `layout` |
| мир разъехался в мультиплеере | `new Random()`, порядок словаря или системное время в правилах | раздел 13 |
| поле обнуляется после загрузки | не добавили его в `SaveSystem` | добавить в запись и в чтение |
| правка не подействовала | собрали не ту конфигурацию | редактор берёт `Debug`, `SimBench` — `Release` |
| «не могу собрать, файл занят» | игра ещё запущена и держит библиотеку | остановить игру и собрать снова |

## 21. Куда дальше

Маршрут, который реально работает — каждый шаг даёт видимый результат:
