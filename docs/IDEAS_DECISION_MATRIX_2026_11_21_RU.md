# Матрица решений и приоритезации идей Deal or Force — 21 ноября 2026

> **Методология.** Все 29 предложений по 7 стратегическим столпам (`A–G`) оценены через OpenRouter Decisions API моделью **`google/gemini-decision-1-20261111`** в трёх воспроизводимых пакетах (суммарная стоимость `$0.00122`):
> - **`score` (`0..4`)**: шкала `0 = отклонить`, `1 = низкая отдача`, `2 = желательно позже`, `3 = высокая отдача (в эту волну)`, `4 = критически важно (must-ship)`;
> - **`noul` (`ship_now`)**: откалиброванная вероятность `p` (`0..1`) того, что предложение стоит отгружать в текущей волне, плюс `confidence`;
> - **`choice`**: прямое распределение вероятностей выбора лучшего варианта среди конкурирующих альтернатив.
>
> Подробный технический и продуктовый разбор каждого пункта — в [RESEARCH_2026_11_21_RU.md](RESEARCH_2026_11_21_RU.md).

## 4. Четыре жёстких «Стоп-гейта» (что сознательно НЕ делать)

1. **НЕ переносить мелкие циклы симуляции в Rust FFI (`B4`, `p=0.043`, 96% conf)** — маршалинг объектного графа проигрывает плотному C# SoA/Span; оставить Rust на крупных аренах (`FrontierField` 3,46×, `DistanceField` 9,57×).
2. **НЕ включать Forward+-only постпроцесс на карте мира (`C5`, `p=0.012`, 99% conf)** — SSAO/SSR/compute ломают Mobile/GLES3 и замыливают политический слой.
3. **НЕ включать агрессивный `PublishTrimmed=true` / Full AOT до первого рабочего APK (`F3`, `p=0.029`, 97% conf)** — риск тихих падений рефлексии и JSON-сериализации; сначала валидировать untrimmed arm64 APK.
4. **НЕ выходить в Steam Next Fest раньше полировки UI и без вертикального среза (`G3`, `p=0.010`, 99% conf)** — у игры ровно один шанс на Next Fest.
