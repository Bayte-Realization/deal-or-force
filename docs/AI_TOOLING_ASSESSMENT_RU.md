# Оценка внешних AI-инструментов: REA, universal-modder, Co-op Anything

## Дополнение 23 октября 2026: REA установлен для Codex

По прямому запросу пользователя REA 6.7.0 установлен вне репозитория, только
для Codex. Системный Node 22.13 не заменялся: использован существующий
комплектный Node 24.22.1. Прежний конфиг сохранён в резервной копии, все восемь
прежних MCP-записей сохранены. CLI и отдельный production-stdio процесс прошли
инициализацию, каталог (207 инструментов, шесть prompts) и проверку сессии.
Статический просмотр собственной .NET-сборки не запускал её и не изменил байты.
Нативные движки анализа и платные провайдеры не устанавливались. Активному Codex
требуется перезапуск/переподключение MCP.

Это обновляет прежнее решение «не ставится» ниже, а не делает REA зависимостью
игры или заменой работе с исходниками. Установка не добавляет конфигурацию
в проектный `.mcp.json` или Git. Подробности и ссылки на первичные сведения:
[проход 23 октября](DEVELOPMENT_PASS_2026_10_23_RU.md#rea-и-публикация).
Следующий раздел сохранён как историческая оценка 22 октября.

## Исходная оценка 22 октября 2026

Проверено на этой машине 22 октября 2026 (Windows, Node v22.13.0, Python 3.13.1,
uv 0.12.0, Godot 4.8 mono). Ниже — что каждый инструмент даёт именно DoF, что
уже подключено и что сознательно не подключено.

## 1. Co-op Anything — не подключается

Это не сетевая библиотека. Это справочник (244 записи на момент проверки),
playbook по десинкам и владению акторами, и MCP-сервер для поиска по нему.
Godot в `playbook/engine-families.md` не упомянут вообще: методика написана
вокруг хуков в чужие бинари (UE4SS, BepInEx, SKSE, javaagent), что для проекта
с открытым исходником и своим authoritative host не нужно.

Полезное для DoF — матрица проверок мультиплеера: два реальных клиента,
полномочия игроков, late join, disconnect/reconnect, восстановление по snapshot,
сохранение, рассинхрон версий/модов, потери/задержка/дубли сообщений. В игре
20 файлов C# уже работают с `MultiplayerPeer`/`ENet`, то есть проверять есть что.

23 октября 2026 тот же stdio-процесс снова ответил на `initialize` и `tools/list`:
8 tools (`search_directory`, `detect_engine`, `game_identity`, `list_docs`,
`read_playbook`, `get_skill`, `get_game`, `validate_entry`), stderr пуст.
В ответе сервер прямо велит агенту начать с `get_skill coop-triage` и
`detect_engine` по папке установки. Для этого репозитория с исходниками это
вредная подсказка рядом с Fennara. В проектный `.mcp.json` запись не входит.
Чек-лист проверок остаётся в
[COOP_ANYTHING_WORKFLOW_RU.md](COOP_ANYTHING_WORKFLOW_RU.md).

Что MCP даёт на практике: `search_directory` и `read_playbook` — это чтение
чужого опыта по сети, `detect_engine`/`game_identity` — только для чужих
установленных игр, для нашей папки бесполезны.

## 2. universal-modder — уже лежит в репозитории, MCP не нужен

В `Tools/UniversalModder/upstream` лежит клон апстрима. `.gdignore` стоит на
родительской папке `Tools/UniversalModder`, поэтому Godot её не импортирует.
Рядом `bta-template` и мост `Tools/BtaBridge`: клон уже использовался для мода
чужой игры, не как MCP этой.

`um` CLI на этой машине рабочий: `uv` создаёт окружение сам.

```
uv run --quiet --project Tools\UniversalModder\upstream python -m um kb search godot
```

Проверено: команда выполняется и отвечает «nothing … matches». В общей базе 131
заметка, и ни одна не про Godot, .NET или C#. То есть под наш движок там опыта
нет — `skills/mod-any-game/references/engines/godot.md` описывает чужую сборку:
`GDPC`-магия в `.pck`, GDRE Tools для восстановления проекта, PCK-overlay через
`load_resource_pack`, override.cfg, Godot Mod Loader. Для проекта, который
собирается из исходников в этом же репозитории, эти маршруты не применимы.

fal MCP (`https://mcp.fal.ai/mcp`, `Authorization: Bearer $FAL_KEY`) не
подключён: `FAL_KEY` в окружении не задан. Без ключа запись в `.mcp.json` была бы
нерабочей, поэтому её нет.

Что действительно может пригодиться точечно:

- `um win` — скриншоты, ввод, запись окна на Windows. Частично дублирует
  `Tools/game-capture.ps1` и runtime-сессии Fennara, но умеет писать видео, чего
  у нас нет.
- `um sprite` / `um render3d` / `um video` — подготовка спрайтов и контактных
  листов, полезно для иконок и трейлеров.
- `um backup` — снапшот сохранений перед рискованным прогоном.
- `um kb` — сначала завести там свои заметки про Godot/C#, иначе поиск
  бесполезен.

Ставить глобально (`uv tool install git+…`) не требуется: локального клона
достаточно, `bin/um` работает от `uv run --project`.

## 3. REA — сейчас не устанавливается

REA — MCP-сервер (npm-пакет `rea-agents`, 6.7.0, ~28,6 МБ распакованного) для
разбора нативных бинарей (Ghidra, IDA, Hopper, JEB, Kuna), .NET-сборок,
JS/Electron и сайтов. Коммерческие дизассемблеры требуют собственной лицензии,
REA их не даёт.

Блокер на этой машине:

```
npm view rea-agents engines
→ { node: '^22.19.0 || ^24.11.0 || >=26.0.0' }
node --version → v22.13.0
npx -y rea-agents@6.7.0 --help → npm warn EBADENGINE, exit 1
```

То есть для установки нужен Node 24 LTS (или 22.19+). Порядок, если решим
ставить: поставить Node ≥ 24, затем `npx rea-agents@latest setup` (интерактивно:
выбор агентов, согласование путей, отдельное согласие на Hopper), флаги
`--client` и `--skill=false` описаны в `docs/installation.md` апстрима.

Стоит ли: у DoF есть исходники, поэтому «понять, как работает фича в чужой игре»
нам не нужно. Реальные сценарии — узкие:

- разобрать чужую Godot-сборку (`.pck`) для сравнения механик;
- проверить, что экспортированная `DealOrForce.dll` не несёт лишнего;
- разобрать нативный краш в сторонней библиотеке.

Против: вес (native-зависимости, включая Frida), отдельная лицензия на IDA,
и высокий расход контекста на сессии дизассемблера. Вывод — держать в резерве,
не подключать «на всякий случай».

## Чего мы не делали

- Не правили чужие конфиги (`~/.codex`, `~/.claude`, `~/.cursor`). Утилита
  `Tools/mcp-survey.mjs` намеренно не имеет `--apply`: конфиг вне проекта
  принадлежит своему владельцу. Для переноса записей есть `--emit <harness>`.
- Не добавляли в `.mcp.json` заведомо нерабочие записи (fal без `FAL_KEY`, REA
  на неподходящем Node).
- `.mcp.json` не отслеживается git, поэтому правка локальная и обратимая.
