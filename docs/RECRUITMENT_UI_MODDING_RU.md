# Настроить окно набора без кода

Готовый пример: `mods/_templates/recruitment_workbench/`.
Он не включён сам по себе и не меняет ни одного правила подготовки войск.

1. Скопируйте папку примера в пользовательскую `mods` игры, вне `_templates`.
   Обычный Windows-путь: `Документы/Bayte Realization/Deal or Force/mods`.
2. Дайте своей папке и `id` в `manifest.json` уникальные имена, поставьте
   `enabled: true`. Остальные поля можно оставить.
3. Измените нужные числа в `interface/roomier.json`.
4. Перезапустите игру и откройте набор войск. Отключение мода возвращает базу.

Не копируйте всё содержимое `game/interface`: загрузчик переопределяет отдельные
ключи, сохраняя остальные. Для одного изменения хватит такого файла:

```json
{
  "metrics": {
    "recruitment.target_pixels": 38
  }
}
```

## Доступные параметры

| Ключ после `recruitment.` | База | Значение |
| --- | ---: | --- |
| `target_pixels` | 32 | Минимальная физическая высота кнопок и поиска. |
| `card_height_pixels` | 66 | Минимальная физическая высота карточки соединения. |
| `two_card_width_pixels` | 440 | Минимальная ширина каталога для двух колонок; ниже — одна с прокруткой. |
| `minimum_font_pixels` | 14 | Минимум основного текста окна. |
| `minimum_caption_pixels` | 12 | Минимум поясняющих подписей. |
| `minimum_heading_pixels` | 20 | Минимум крупных заголовков. |

Для защитного расчёта шрифтов допустимый минимум ограничен 8–36 px;
авторский размер и предпочтение масштаба игрока также учитываются.
Числа — минимумы, не команда обрезать более длинную надпись.
Параметры текста этого окна не меняют шрифты остального HUD.

Значения примера: 38/78/560 px и 16/13/22 px. На узком экране карточки
становятся одноколоночными, а действия заказа остаются вне прокрутки.

## Контент и переводы

Каталог берёт все соединения из действующего `UnitTypeCatalog`, а не из
зашитого списка семи кнопок. Определения лежат в `common/units/`, переводы —
в `localization/english` и `localization/russian` внутри мода.
Изменение стоимости или характеристик соединения — уже баланс, не оформление;
оно требует собственной проверки и не входит в этот безопасный UI-пример.

Новые файлы интерфейсного примера — данные и описание. Компилятор, GDScript,
DLL, воркер или исходники Godot не нужны. В игру не устанавливались сторонние
зависимости и не менялись пользовательские активные моды.

Проверка примера: native probe загружает его реальный `interface` тем же
`InterfaceSkin.LoadDirectory`, который использует ModLoader; измеряет карточку,
текст и поиск, затем возвращает все шесть исходных значений. Это проверка
переопределений и живого UI, не утверждение, что каждый маршрут установки
пакета или произвольный мод уже проверен.

Общий вводный справочник: [первый мод](MODDING_QUICKSTART_RU.md).
Полноценный визуальный no-code конструктор любых механик остаётся отдельной задачей.
