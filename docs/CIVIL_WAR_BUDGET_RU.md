# Годовой лимит гражданских войн

Проверка 14 октября 2026 года. Это исправление устойчивости существующей механики,
не новая модель политического населения и не увеличение частоты распадов.

## Причина

`CivilWarWorldPerYear` раньше считал записи `civil_war` в мировой хронике. Хроника
оставляет только последние 2048 фактов для интерфейса. Если мир создавал много
других новостей, ещё актуальные гражданские войны выпадали из этого списка:
годовой лимит разрешал новые войны. Так же мог исчезнуть существующий множитель
риска после военного переворота.

## Исправление

- Кампания хранит `CivilWarBudget.StartsByDay`: число реально начавшихся восстаний
  по игровым дням. Учёт подключён к существующему успешному пути `SecessionEvents`,
  который создаёт факт `civil_war`, а не только к случайной проверке ИИ.
- Окно прежнее: возраст **меньше 365 дней**. На 364-й день событие учитывается,
  на 365-й — нет. Не больше 365 дневных счётчиков независимо от длины кампании.
- Несколько действительных восстаний одного дня увеличивают один счётчик.
  Повторная проверка дня сама по себе не создаёт события. Экстремальное число
  событий насыщается на `int.MaxValue`, не переполняется в отрицательное число.
- Истёкшие записи очищаются и при отключённой механике. Просмотр количества
  не изменяет мир и не потребляет случайные числа.
- Бюджет копируется в сохранение/сетевой снимок и входит в отпечаток мира.
  Порядок словаря не влияет на отпечаток; пустой бюджет не добавляет новый маркер.
- Военный переворот/контрпереворот отдельно сохраняет `LastMilitaryCoupDay`.
  Общий `LastCoupDay` продолжает обслуживать прежние периоды восстановления.
  Отрицательный sentinel означает отсутствие переворота, будущая дата не считается.
  Его прежнее окно остаётся включительным: до `CivilWarCoupMemoryDays` дней.
- Только военная ветка (`Military coup`) обновляет отдельную дату. Последующий
  институциональный переворот не стирает недавний военный: множитель остаётся,
  пока не истекло именно его окно. Институциональные переходы сами по себе
  **не получают нового множителя x2**. Порог стабильности, базовая вероятность,
  защита игрока, лимит мира и сроки восстановления не изменены.

## Старые сохранения

Отсутствующее поле бюджета означает старый формат. При восстановлении, один раз:

1. Берутся точные сохранившиеся факты `civil_war` из хроники.
2. Дополняются гражданскими войнами с положительной датой начала, совпадающей
   с сохранённым `LastCivilWarDay` участника, и подтверждёнными парами родитель/повстанцы.
3. Один факт определяется парой «день, новая страна». Хроника, война и даты
   родителя/повстанцев не превращают его в три разных восстания.

Если остались только неоднозначные даты без войны/родственной связи, доказано лишь
«хотя бы одно восстание в этот день». Используется этот нижний предел, не выдумывается
дополнительное событие на каждого участника. Полную уже вытесненную историю восстановить
невозможно; начиная с нового бюджета новые события больше от обрезания хроники не зависят.

`LastCivilWarDay == 0` без точного факта — старый sentinel, не новое событие в день ноль.
Начальные сценарные гражданские конфликты сами по себе не занимают бюджет.
Даты переворота/восстания, периоды восстановления, RNG и существующая хроника не стираются.
Для старого положительного `LastCoupDay` без сохранённого outcome выбран прежний военный
множитель: если вид переворота уже утрачен, надёжнее сохранить известный недавний переворот,
чем потерять его только из-за размера списка новостей.

Отдельная военная дата старого сохранения восстанавливается из сохранившихся
`coup`/`coup_counter`, явного военного outcome либо этого fallback. Явный институциональный
outcome не превращается в военный, но не мешает восстановить более ранний военный факт.
Если более ранний военный факт уже исчез и единственная оставшаяся дата относится к
институциональному перевороту, его утраченную дату восстановить нельзя. Новые сохранения
больше эту информацию не теряют.

## Проверки

`Tools/FormableTests/CivilWarBudgetTests.cs` проверяет вытеснение 2049 фактов,
военную/институциональную ветки, обе временные границы, negative/future sentinels,
365-счётчиковый предел, повторную проверку дня и отсутствие расходования RNG.
Отдельная фикстура реально создаёт восстание, сохраняет и восстанавливает его
авторитетный сетевой payload с одинаковым отпечатком мира. Legacy-фикстуры проверяют
дедупликацию разных свидетельств, сохранность recovery/coup cooldown и отсутствие
выдуманного события из нулевых полей старого сохранения.
Последовательность «военный → институциональный → вытеснение хроники → загрузка»
отдельно сохраняет прежнюю вероятность; legacy-версия с уцелевшим военным фактом тоже
проверяется.

Это не доказательство столетнего баланса и не гарантия отсутствия всех вылетов движка.
