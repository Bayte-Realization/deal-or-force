# Моддинговая структура: аудит 6 ноября

Запрос пользователя — единообразие, один понятный путь редактирования и минимум
ручного кодинга. Это аудит и очередь миграции, **не заявление, что вся структура
уже переведена на новый формат**. Рабочий контракт персонажей описан отдельно в
[MODDING_CHARACTERS_RU.md](MODDING_CHARACTERS_RU.md).

## Уже исправлено в этом срезе

- Удалён старый `game/common/console/00_touchgrass.json` и отдельный ConsoleVerse.
  Текст команды теперь берётся по `console.touchgrass.verse` из обычной локализации,
  поддерживает тот же YAML overlay и английский fallback, что остальной интерфейс.
- Частичный `history/rulers` больше не заменяет всю страновую запись: один портрет
  наследует остальные имена/возраст/министров. Министр наследует свои пропущенные поля.
- Офисные эффекты событий и их условия валидируются в Content editor до применения.
- В редакторе страны выбираются портреты с предпросмотром. Он сам пишет
  `history/rulers` вместе с остальными документами страны; пользователь не обязан
  знать расположение каждого поля. Сохранение не меняет текущую кампанию.

## Что действительно обнаружено по регионам

1. `map_data/source_tables.json`, секция `states`, — исходная таблица стабильных
   географических ID (не постоянные владельцы кампании).
2. `map_data/state_regions/00_region_overrides.json` — географические уточнения,
   полигоны, разделение исходных регионов. В TerritorialTopology остаются и
   скомпилированные поправки. ResetCatalog пока читает только **первый** файл папки;
   это не соответствует обычному обещанию «все файлы, позже побеждает».
3. `map_data/unclaimed_regions/00_regions.json` — координатная привязка Бир-Тавиля:
   у ничейной провинции нет исходной административной карточки. Код не отбирает
   чужую землю по этой координате.
4. `history/states/2024/unclaimed.json` — обычное начальное состояние регионов
   Антарктиды: owner none, станции/постройки, население, претензии и договорный режим.

Итак, Бир-Тавиль и Антарктида после загрузки — обычные ScenarioState. Но авторинг
географии раздроблен, и название отдельной папки с поправками скрывает порядок
источников. Удалить её без переноса логики — потерять часть карты, не очистить её.

Следующий законченный блок стандартизации:

- Единое авторское место географических определений регионов, стабильные ID,
  один задокументированный schema и одинаковое правило overlay JSON/YAML.
- Перенести туда исходные определения, поправки и создание отсутствующей карточки
  ничейной земли; не маскировать простое переименование папки под полную миграцию.
- Датированная история остаётся отдельным слоем значений сценария, но использует
  те же ID. Справочная страна источника не становится вечным владельцем.
- Старые пути читаются адаптером совместимости для уже написанных модов с понятным
  предупреждением, без дублирования базовых данных в двух папках.
- Редактор региона показывает одну форму, сам сохраняет нужные документы и проверяет
  конфликт ID, границы, население, владельца и привязки городов. Карта выбирает регион.
- Сравнение карты до/после: провинции, границы, площадь/население, Бир-Тавиль,
  Антарктида, disputed states, загрузка старого сейва и несколько слоёв модов.
  Миграция не должна тайно перекроить мир или изменить ID старого сохранения.

## Города: фактическое поведение и следующий шаг

CityCatalog привязывает точку к провинции, регион берётся из ProvinceToState,
текущая принадлежность — из земли. Поле country уже помечено как ISO источника,
не собственность. Population сейчас — статическая оценка агломерации для важности
и подписи, не дополнительная порция населения государства.

Запрос на большее число городов остаётся открытым. Есть локальный первичный
Natural Earth DBF и штатный компилятор с порогом SCALERANK 7. Расширение делать
воспроизводимо, с проверкой координат/дубликатов, переводами и бюджетом городских
подписей. Нельзя обещать актуальную перепись или живую городскую демографию по
старой оценке источника. Для динамических городов нужны доли населения внутри
региона и тест сохранения общей численности, не прибавление городов поверх региона.

## Редакторы: целевой пользовательский путь

Создать/выбрать мод → выбрать объект на карте/в списке → изменить понятные поля и
изображения → увидеть результат/ошибки → сохранить. Пути и синтаксис — работа
редактора, расширенные скрипты — опция. Нынешний универсальный property editor не
объявляется визуальным конструктором любых механик: поля YAML, граф событий,
перетаскивание файлов, полноценный cast персонажей/связи ещё требуют работы.
