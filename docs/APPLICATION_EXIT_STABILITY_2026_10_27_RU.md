# Обычный выход из игры: музыка, пауза и повторные запросы

Дата: 27 октября 2026. Версия: ReimAlpha 2 0.9.0.

## Результат и границы

Исправлен **пользовательский путь выхода на рабочий стол**: до завершения дерева
игра останавливает звук и освобождает ссылки на потоки, оставляя аудиосерверу
короткое время на завершение работы. В проверенных сценариях больше нет прежней
ошибки двух Ogg-ресурсов. Это изменение продукта, а не удаление музыкального
менеджера только в тесте.

Закрыто и старое предупреждение **251 ObjectDB / RefCounted с reference count 0**
в проверенном выходе из кампании: причиной оказались не полученные результаты
фоновых запросов флагов. Итоговая матрица штатного выхода — **101 native PASS,
0 ERROR/WARNING, matrix.failures=0**, без принудительного GC. Общий визуальный/
стабилизационный milestone всей игры этим не объявлен завершённым.

## Изменения

- `ApplicationExit` — единый путь кнопок меню/паузы, выхода из невосстановимой
  загрузки, существующей консольной команды и события закрытия главного окна.
  Подключён в обеих входных сценах, без нового autoload или изменения сцен.
- При выходе дерево приостанавливается; аудиоплееры останавливаются, их `Stream`
  очищается. Таймер 0,1 с работает независимо от паузы/масштаба времени, затем
  ожидается кадр перед окончательным `SceneTree.Quit`.
- Повторные запросы не запускают несколько очисток; сохраняется первый ненулевой
  код ошибки. Поздний обычный запрос не затирает ошибку.
- MusicDirector не возобновляет звук через поздний FollowScene, кадр или завершение
  трека после начала выхода. Та же очистка используется при выходе узла из дерева.
- Основные ветви ExportVerification пользуются тем же production-путём. Только
  явно обозначенная development-проверка `raw` намеренно воспроизводит прямой Quit.
- Результаты фоновой загрузки флагов теперь принимаются даже для не показанных
  флагов: до 16 готовых результатов за кадр, без ожидания незавершённого запроса.
  Это продолжается на паузе и после возвращения в меню. Сброс кэша переносит
  старые запросы в очередь завершения, а не забывает их; их текстуры не возвращаются
  в новый кэш. Дублирующиеся пути сохраняются как отдельные принятые запросы.
  На выходе ожидаются оставшиеся запросы не дольше 2 с; недогруженные по дедлайну
  явно отмечаются предупреждением, не скрываются и не считаются чистым выходом.

Это соответствует различию между закрытием окна и прямым завершением дерева:
[документация Godot о quit requests](https://docs.godotengine.org/en/stable/tutorials/inputs/handling_quit_requests.html).
Старый GDScript BootGuard не переписан: аварийный путь должен работать даже при
недоступном .NET. Произвольный прямой Quit из стороннего мода, принудительное
завершение ОС и падение процесса не объявлены перехваченными.

Состояние кампании, RNG, команды, сохранения и сеть не менялись; автоматического
сохранения на выходе нет. Принудительный GC в production не добавлен.

## Проверки

Артефакты: `build/.application-exit-20261027/` (локальные, игнорируются Git).
Каждый нативный запуск использовал отдельный снимок управляемых сборок, чтобы
параллельные сборки других агентов не заменяли DLL в работающем процессе.

Чистые managed-проверки:

- ApplicationExit: **19 PASS** — самостоятельный минимальный runner и отдельно
  узкий режим общего стенда через `Tools/dev.ps1 -Test`.
- Music transition: **41 PASS**; music: **35 PASS**; interface type: **72 PASS**.
- Игра собрана без ошибок/предупреждений. Полный общий стенд и новый SimBench
  в этом проходе не заявлены.

Итоговая матрица `final-exit/matrix.json`:

|---|---:|---|---|
| Кнопка главного меню EN / RU | 11 / 11 | 0 / 0 | 0 / 0 |
| Сигнал CloseRequested главного окна | 10 | 0 | 0 / 0 |

Восемь чистых некампанейных сценариев: **90 PASS**. Кампания: ещё **11 PASS**,
проверена неизменность fingerprint, сброс кэша с двумя запросами одного пути и
нормальный выход с двумя оставшимися запросами. Нет ни Ogg ERROR, ни ObjectDB
warning; `matrix.failures=0`. Это headless-проверка живого
Godot 4.8 beta1, не тест физического Alt+F4 и не приёмка свежего экспортного EXE/PCK.

Исходная ошибка сохранена в первом `raw.stderr.log`: четыре ObjectDB и два Ogg-
ресурса. Прямой `raw` в итоговой матрице тоже красный; он не входит в 101 PASS и
не считается исправленным продуктовым путём. Один промежуточный raw оказался
чистым — дефект воспроизводится не каждый раз.
Первый crossfade-probe попытался запустить смену во время начального fade-in;
исправлен сам probe: он ожидает настоящую огибающую, не сбрасывая production-переход.
Оба итоговых crossfade-прогона чистые.

## Как локализована утечка флагов

До исправления флагов `matrix-final/matrix.json` содержал 10 функциональных PASS
кампании, но один warning-gate failure. `campaign-verbose.log` показал ровно 251
`RefCounted`, все с reference count 0, без Ogg ERROR. Отдельный opt-in diagnostic
с Collect/WaitForPendingFinalizers/Collect также оставил 251 объект
(`gc-diagnostic/matrix.json`); принудительная сборка мусора не помогла.

Read-only трасса managed-wrapper IDs (`wrappers/`) не обнаружила 251 простую
обёртку RefCounted в C#. Просмотр цепочки предзагрузки обнаружил WarmFlags:
запрашивались все флаги, но LoadThreadedGet вызывался только для отображённых;
ForgetFlags забывал остальные запросы. У загрузчика собственный токен запроса,
а повторные запросы одного пути требуют соответствующего числа получений:
[ResourceLoader API](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html#class-resourceloader-method-load-threaded-get),
[официальная реализация токенов](https://github.com/godotengine/godot/blob/master/core/io/resource_loader.cpp).
После исправления этого владения обычный прогон без диагностического GC стал
чистым. Чужие RefCounted не освобождались принудительно, engine/addons не менялись.

Дополнительная трасса wrapper IDs доступна только development-флагом; внутреннее
поле диагностируется условно, недоступный tracker не является production-зависимостью.

Первая Fennara diagnostics не нашла подключённого редактора; после последнего
набора C#-правок повторная проектная диагностика не вернула результат за ограниченное
ожидание и её ожидание было прекращено. Это **не успешная диагностика**;
пользовательский редактор ради проверки не перезапускался. Успешная компиляция
(последний `flag-lifecycle-final-build.log`, 0 ошибок/предупреждений) и нативные
логи — отдельные полученные доказательства. Полный стенд, долгий soak, раннее
закрытие во время стартовой предзагрузки логотипов и физический Alt+F4 не проверены.

GitHub, новый EXE/PCK и полная упаковка в этом проходе не выполнялись.
Rust не используется; BTA не затронут. Чужие процессы и партии не останавливались.
