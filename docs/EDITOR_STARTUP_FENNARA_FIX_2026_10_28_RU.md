# Инициализация редактора: лишние обходы Fennara и Dialogue Manager

28 октября 2026. Локальный ремонт инструментов, не новая версия игры.
Автор разрешил исправить Fennara без отключения и закрыл удерживавший DLL
редактор. Установлены исправления сканеров; первичное окно инициализации
сменилось рабочим редактором. Целевые проверки успешны; чистый замер повторного
открытия ограничен последующими параллельными запусками, описанными ниже.

## Что было найдено

Исходный Godot `--editor` PID 82116 был неотзывчив более двадцати минут.
Большая часть времени не объяснялась активной C#-компиляцией: управляемая
выборка показывала ожидающие thread-pool/MSBuild logging threads. WCT не
обнаружил цикла, но это само по себе не исключает зависание.

В нативных выборках главный поток находился в файловых системных вызовах.
Directory handle указывал на `build/luau-worker/.../Release`, затем на
`tmp_playtest/game-build-084c/game/localization/english`. Адреса в стеке
попадали в нативный Fennara. Это **кандидаты адресов, не полный backtrace**
без символов. Исходники точно установленного Fennara 0.4.3 подтвердили два
самостоятельных обхода, не учитывавших `.gdignore`, отдельные вложенные
проекты и junction-ссылки. `.gdignore` у `build` существовал до ремонта.

После первого исправления обнаружены ещё скрытые снимки инструментов
`.mimosa/hook-state`: поиск C#-проектов не исключал произвольные скрытые папки.
После этого Fennara подключался, но инициализация ещё задерживалась.
Новый закреплённый directory handle показал
`Tools/ManagedModTests/bin/Release/net8.0/game/localization/russian`.

Второй подтверждённый дефект — `DMCache.prepare()` Dialogue Manager 4.0.3.
Он синхронно вызывается из `_enter_tree()` и рекурсивно ищет `.dialogue`,
пропуская только `.godot`/`.tmp`, но не `.gdignore`, другие скрытые каталоги
или ссылки. Поэтому исправить только Fennara было недостаточно.

## Исправление без отключения функций

Fennara пересобран из `v0.4.3`, commit
`0abbac3b3a1cb46bbce4f90e8cebc6a3e5d61ec6`, с его закреплённым godot-cpp
`e83fd0904c13356ed1d4c3d09f8bb9132bdc6b77`.
Менялись только `src/csharp/project.cpp` и `src/file_utils.cpp`:

- не входить в подкаталог с `.gdignore` или своим `project.godot`;
- не следовать directory links/junction;
- поиск C# пропускает скрытые служебные папки;
- общий индексатор также исключает `bin`, `obj`, `node_modules`.

Обычные вложенные C#-библиотеки и явная настройка project_directory сохранены.
Разрешение явных `ProjectReference` остаётся задачей MSBuild. Не менялись
MCP-маршрутизация, веб-интерфейс, daemon/CLI, политика разрешений аддонов,
автозагрузки или версия плагина. Глобальные зависимости не устанавливались.

В Dialogue Manager ограничен только поиск `.dialogue`: те же границы,
проверка `DirAccess.open()` на null, явный `list_dir_end()`.
Импортёр, редактирование диалогов, автозагрузка и вкладка не выключены.
Два патча, исходники тестов и лицензии сохранены в
[Tools/EditorStartup](../Tools/EditorStartup/README.md), потому что установленные
аддоны локально игнорируются Git. Официальное обновление может заменить hotfix.

Попутно реальный импорт выявил ошибку свободного Luau-примера:
после `return Event` были ещё определения функций, а `.lua` разбирался
адаптером как Godot-класс. Возврат перенесён в конец, файл получил штатное
модульное имя `mods/luau_events/war_damage.mod.lua`. Все функции и числовые
эффекты сохранены; подключение этих примеров к игровым событиям не заявлено.

## Что проверено

Нативная сборка SCons `platform=windows target=editor arch=x86_64 -j4` завершилась
с кодом 0. Probe собран с тем же godot-cpp и `/MT` CRT.

**14 native PASS**, `SCAN_VERIFY failures=0`, exit 0, без ERROR/WARNING.
Настоящие изменённые C++-сканеры вызываются внутри Godot через маленький
тестовый GDExtension. Подменена только addon access policy — deny by default.
Проверены ложные проекты в `.gdignore`, вложенный Godot-проект, скрытый снимок,
реальный циклический junction, выбор корневого проекта, обычная вложенная
библиотека и явный некорневой project_directory. Отдельно подтверждено, что
fixture-скрипт без явного маркера отказывается писать (ожидаемый exit 2).

**9 Dialogue PASS**, `DIALOGUE_SCAN_VERIFY failures=0`, exit 0.
Из настоящего `dialogue_cache.gd` извлекается и компилируется дословно функция
поиска, без сторонних глобальных типов остального плагина. Проверены корневой
и вложенный диалог, исключённые деревья, junction, отсутствие каталога и
явный обычный подкаталог. Это не полный функциональный тест Dialogue Manager.

**2 Luau PASS**, `LUAU_PARSE_VERIFY failures=0`, exit 0: настоящий установленный
адаптер загружает и компилирует исправленный модуль. В fixture использовалась
отдельная byte-copy DLL: первый тест общей DLL столкнулся с занятой Godot
`~`-копией и не засчитан. События в кампании здесь не исполнялись.

Финальные PowerShell-помощники прошли parser-проверку; нативная выборка
выполнялась и для явно указанного проверенного потока. Поток возобновляется
в `finally` до получения пути и разрешения символов. Нет debugger attach,
инъекции, полного дампа или загрузки символов из сети.

## Проверка настоящего редактора

После исправления обоих плагинов запущен основной проект, PID 62964,
`editor-combined.log`. Fennara подключён именно к
`D:/Godot Projects/deal-or-force-godot-4-8/`, одна активная сессия.
Чтение `res://Scenes/MainMenu.tscn` через MCP успешно: Control/MainMenu,
настоящий `MainMenuScene.cs`. Снимки редактора просмотрены: первичного модального
окна больше нет; затем видны Scanning Files 66%, Scanning actions 47% и
дальнейшая работа интерфейса. В 01:10:32 статус подтвердил
**`Editor filesystem: ready`, `Asset tools ready: yes`**.

Godot сам переписал старый filesystem_cache10: с 46 438 до 7 736 строк.
Ручного массового удаления импортов не было. Этот первый проход включал
перепроверку старого большого кэша и импорт, поэтому его длительность —
не доказательство времени следующего открытия и не контролируемый A/B.

Изолированная фоновая сборка Fennara завершилась успешно в 01:12:17,
197.473 s по его журналу; рабочая `.godot/mono/.../Debug` не заменялась.
Единственный вызов общей `script_diagnostics` (`local-tool-54`) клиентским
ожиданием завершился таймаутом, но работа продолжилась. Журнал подтверждает
переход после фоновой подготовки к отдельной forced-refresh сборке. До
получения её результата редактор PID 62964 был закрыт **извне**; новый
PID 49608 появился в 01:16:45 без моего проверочного `--log-file`.
Поэтому финальный полный diagnostic scan не восстановлен и не объявлен
зелёным. Новый редактор не останавливался, дублирующая сессия не запускалась.
В 01:20 подтверждены ещё два чужих `--headless --editor --quit` того же корня:
реальные engine PID 58004 и 58152, запущены в 01:18:12 рядом с GUI PID 49608.
Конкурирующие запуски могли менять/блокировать общие импорты и рабочие DLL,
поэтому их длительность **не используется как чистый warm-start benchmark**.
Ни один из этих трёх процессов не завершался мной. Повторный чистый замер
остаётся открытым: нужна одна согласованная редакторская сессия этого проекта.

## Ограничения

Первый GUI-запуск не был полностью чист от сообщений: появилась отдельная
ошибка GodotTools beta `HotReloadAssemblyWatcher.RestartTimer()` при уведомлении
окна и сообщения сторонних плагинов (Formatter menu, MCP toolkit version/tested
engine, CSV без переводов). Зафиксирована также отсутствующая импортная копия
`demo/assets/fx.png`; переимпорт всего проекта или удаление demo не выполнялись.
Ошибка старого Luau-имени была до его исправления.
Эти сообщения не скрывались и не объявлены исправленными одним exit 0.

Fennara MCP работает в `legacy_unbound`; в проверке подключён один проект,
изоляция нескольких одновременных проектов не сертифицирована, конфигурация
маршрутизации без отдельной задачи не менялась. После появления конкурирующих
сессий новые диагностические/изменяющие MCP-запросы не запускались.
Не обещается мгновенный запуск
при любом размере ассетов, изменениях сторонних инструментов или обновлении.
Формального game-dev benchmark/ускорения «в N раз» здесь нет.

Полный стенд, SimBench, игровая партия, новый EXE/PCK, GitHub/upstream PR
не выполнялись. В игре не менялись правила/сеть/сейвы, не интегрировались
новые языки; Rust и BTA не затронуты. Чужие редакторы не завершались:
PID 46144 закрыл автор; собственные зависшие проверочные процессы были
остановлены только после сверки PID/командной строки и попытки обычного закрытия.
