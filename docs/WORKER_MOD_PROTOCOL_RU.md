# Протокол воркера v1: как подключить сторонний язык как мод-мозг

Это единственная дверь, через которую другой язык или фреймворк влияет на игру, **не ломая
lockstep**: воркер не получает мир, не считает экономику и не двигает армии. Он получает
снимок, думает у себя и **просит** команды; ядро их проверяет и применяет в общем порядке,
как если бы их нажал игрок.

Реализация: `Scripts/Modding/WorkerModBackend.cs`. Загрузка: `Scripts/Modding/ModLoader.cs`.

## 1. Как объявить воркер (manifest.json мода)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `worker_executable` | `""` | путь к исполняемому файлу относительно папки мода |
| `worker_script` | `""` | один аргумент, передаётся как `argv[1]` (например, путь к скрипту) |
| `worker_timeout_ms` | `500` | 50…15000; по истечении процесс убивается вместе с деревом |
| `worker_interval_days` | `7` | как часто вызывать `day_advanced` |

## 2. Когда вызывается

| Хук | Когда |
|---|---|
| `load` | один раз при загрузке мода |
| `campaign_created` | один раз при создании кампании |
| `day_advanced` | раз в `worker_interval_days` дней, и **не дважды за один день** |

## 3. Правила игры

1. **Один запуск — один процесс.** В stdin кладётся **один** JSON-объект запроса, ввод
   закрывается. Процесс пишет **один** JSON-объект ответа в stdout и завершается с кодом 0.
2. **stdout — только ответ.** Любая диагностика идёт в stderr: он читается (до 16 КБ) и
   попадает в лог при ошибке.
3. **Пределы:** запрос ≤ 2 МБ, ответ ≤ 256 КБ, stderr ≤ 16 КБ, глубина JSON ≤ 16,
   `logs` ≤ 32 сообщения по ≤ 1024 символа, `commands` ≤ 32.
4. **Мультиплеер:** при более чем одном человеческом месте воркер отклоняется — он не
   lockstep-пир.
5. **Одна ошибка отключает воркер до конца кампании** (таймаут, ненулевой код, превышение
   размера, неизвестная команда). Это сделано нарочно: сломанный мод не должен тормозить
   каждый игровой день.
6. **Ответ применяется атомарно:** если хотя бы одна команда невалидна, не применяется

## 4. Запрос (что видит воркер)

```json
{
  "protocol": 1,
  "event": "day_advanced",
  "day": 9736,
  "seed": 947986505,
  "capabilities": ["set_feature", "improve_relations", "reaffirm_alliance",
                   "enact_policy", "manage_debt", "course_shock"],
  "nations": [
    {
      "tag": "FRA", "name": "France", "population": 68.2, "stability": 0.61,
      "treasury": 12.4, "public_debt": 210.5, "debt_arrears": 0.0, "payment_arrears": 0.0,
      "credit_confidence": 0.74, "debt_condition": "Normal",
      "course": "industrialisation", "course_initialized": true,
      "inertia": 0.32, "shock": 0.0,
      "convictions": { "labour": 0.31, "order": 0.55 },
      "laws": [ { "slot": "labour", "id": "eight_hour_day", "target_tag": "", "region": 0 } ],
      "promise": "", "promise_completed": false, "promise_succeeded": false
    }
  ],
  "features": { "union_cohesion": true, "formable_nations": true }
}
```

Важное:

- **Страны адресуются тегом**, числового `id` в снимке нет — и не будет: id это индекс
  в списке, он не переносим между кампаниями.
- `capabilities` — то, что ядро **рекламирует**; `study_doctrine` и `propose_diplomatic_act`
  парсер тоже принимает, хотя в списке их нет.
- Порядок `nations`, `convictions`, `laws`, `features` отсортирован: один и тот же мир даёт
  один и тот же документ.
- **Новые поля добавлять можно, удалять нельзя** — воркеры, написанные раньше, их читают.

## 5. Ответ (что воркер может попросить)

```json
{
  "protocol": 1,
  "logs": ["repaying the largest debt"],
  "commands": [
    { "type": "manage_debt", "issuer": "FRA", "action": "repay", "amount": 0.5 }
  ]
}
```

| `type` | Обязательные поля | Проверка ядром |
|---|---|---|
| `set_feature` | `feature`, `enabled` | id существует; игрок не отменяется |
| `improve_relations` | `issuer`, `target` | обе страны существуют, разные |
| `reaffirm_alliance` | `issuer`, `target`; необязательные `program`, `cancel` | пара существует |
| `enact_policy` | `issuer`, `policy`; необязательные `promise`, `target`, `region` | политика существует, регион ≥ 0, цель существует |
| `manage_debt` | `issuer`, `action` (`borrow`/`repay`/`restructure`), `amount` | конечное число; для `borrow`/`repay` > 0 |
| `course_shock` | `issuer`, `strength` (0…1], `reason` (≤ 256) | конечное число |
| `study_doctrine` | `issuer`, `branch`, `node`; необязательный `rush` | ветка и узел существуют |
| `propose_diplomatic_act` | `issuer`, `target`, `act` | акт существует, страны разные |

Предел батча — 32 команды, и **вся пачка отвергается** при первой невалидной: воркер не
может применить полшага.

## 6. Что воркеру делать нельзя (и почему)

- **Держать состояние между днями.** Процесс живёт один вызов; всё, что нужно помнить,
  лежит в мире (законы, кулдауны, курс) — иначе два игрока получат разные миры.
- **Писать в stdout что-либо, кроме ответа.** Один лишний `print` = невалидный JSON =
  воркер отключён до конца кампании.
- **Работать дольше `worker_timeout_ms`.** Бюджет по умолчанию 500 мс — это кадр.
- **Открывать сеть, читать чужие файлы, спавнить долгоживущие процессы.** Это не песочница:
  защита здесь — контракт, а не изоляция. Для недоверенного кода есть Luau и RISC-V песочница.
