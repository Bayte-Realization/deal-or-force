# Действия модов во фронтенде

Generic foundation от 14 октября 2026. Контракт не содержит названий внешних игр, путей к launcher или команд запуска процессов.

## Описание без запуска кода

В `manifest.json` включённого мода можно объявить:

```json
{
  "id": "companion_bridge",
  "frontend_actions": [
    { "id": "launch", "caption": "Open companion game" }
  ]
}
```

`ModLoader.Discover()` публикует действия только уже разрешённых зависимостями включённых модов, не content packs. Это обычные данные: обнаружение и `FrontendActions()` не загружают DLL и не выполняют обработчики. Исходная подпись `Caption` служит ключом локализации; интерфейс переводит её своим обычным `Tr`/`Loc.Get`.

`ModFrontendActionDescriptor` содержит `FullId`, `ModId`, `Id`, `Caption`. Полный стабильный идентификатор примера — `companion_bridge:launch`. Действия не привязаны к индексу кнопки или переведённому тексту.

Идентификаторы состоят из ASCII-букв, цифр, `_` и `-`: максимум 128 символов для package ID и 64 для local action ID. Двоеточие зарезервировано разделителю полного ID. Caption после удаления краевых пробелов должен быть непустым, не длиннее 160 символов, без управляющих символов. Повторные ID сравниваются без учёта регистра и не заменяют первое объявление. На пакет читаются не более 32 объявлений, в общем каталоге не более 512 действий. Ошибочные записи пропускаются с диагностикой пакета.

## Обработчик принадлежит загруженному модулю

Скомпилированный C#-мод регистрирует обработчик в своём runtime-контексте:

```csharp
public void OnLoad(ModContext context)
{
    context.RegisterFrontendAction("launch", () =>
    {
        // Здесь находится логика этого мода, не базовой игры.
        return "Companion requested.";
    });
}
```

Регистрация возвращает `false` для необъявленного local ID, занятого обработчика или отозванного контекста. Регистрация сама не выполняет callback. Package ID берётся из контекста loader, мод не передаёт чужой package ID.

После явного действия пользователя фронтенд вызывает:

```csharp
bool delivered = loader.TryRunFrontendAction(fullId, out string note);
```

До `StartCode` вызов отказывает: наличие подписи не даёт разрешения исполнить мод. Когда код успешно загружен, callback возвращает сообщение для интерфейса. `delivered` обозначает успешный вызов обработчика, а не гарантированный успех внешней программы: специфичный результат объясняет сам мод.

Исключение callback перехватывается и возвращает безопасное `Mod action failed.`, без текста исключения, который может содержать приватные пути или токены. Недоступное действие возвращает `Mod action is unavailable.`. Фронтенд должен показывать эти сообщения пользователю и переводить общие сообщения отказа.

## Срок жизни

- `StopCode()` сначала отзывает обработчики, затем освобождает модули и их load contexts.
- `StartCode()` освобождает прошлый runtime перед новой загрузкой.
- Повторное discovery меняет поколение каталога и отзывает прежние действия; удержанный старый `ModContext` больше не может регистрировать обработчики.
- При исключении в `OnLoad` или `OnCampaignCreated` регистрация неудавшегося экземпляра отзывается и его `IDisposable` освобождается.
- Освобождение одного экземпляра отзывает только принадлежащие ему обработчики; старый экземпляр не может удалить новый обработчик того же ID.

Managed-моды остаются доверенным кодом с возможностями процесса игры. Этот контракт не является OS sandbox. Он предотвращает случайное исполнение во время discovery и утечки устаревших UI-handler, но не ограничивает права явно включённого runtime-мода.

## Проверка и ограничения

Engine-neutral regression seam — `ModFrontendActionCatalog`. `dotnet run --project Tools/FormableTests -- --mod-frontend-only` проверяет metadata-only discovery, explicit dispatch, namespace/ownership, остановку/перезагрузку/смену профиля, ошибки и пределы каталога. Адаптер `ModLoader` компилируется вместе с основной игрой.

В этом foundation нет auto-launch, автоматического создания кнопок, Lua/GDScript/worker регистратора действий или выбранной UX-модели ожидания загрузки кампании. UI-adapter обязан ждать runtime, не вызывать `StartCode` ради получения подписей и не запускать действие при обновлении меню. Перенос конкретного BTA launcher, его кнопок и упаковки — отдельный интеграционный этап.
