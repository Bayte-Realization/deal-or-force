# Устойчивость кампании и сохранения

Проверено 8 октября 2026 года. Конкретные исправления не означают гарантии
отсутствия любых падений движка, драйвера или стороннего мода.

## Причина переполнения

На копии старой кампании Таиланда первая бесконечность воспроизвелась 8 июня 2122 года:
`ATA.Gdp = Infinity`. Служебная географическая запись Антарктиды с нулевым населением
продолжала участвовать в экономике. Остаточный выпуск оружия считался от текущего
номинального ВВП, а стоимость выпуска снова увеличивала ВВП. Получилась положительная
обратная связь «ВВП → оружие → ВВП», затем Infinity/NaN.

NaN опасен не только для JSON: `NaN < порог` возвращает false. Без отдельной проверки
это может обходить условия политических событий. Нечитаемый сейв и неправдоподобный
распад могут иметь общую численную причину, но это не доказательство происхождения
каждого ранее показанного анклава.

`ProductionCapacity` сохраняет физическую базу один раз и масштабирует её по жителям,
не по текущим ценам. Страны без жителей/земли не производят остаточную промышленность.
При разделении страны база делится, а не калибруется заново по завышенному ВВП.
ATA остаётся для географии и совместимости; это не населённое начальное государство
в выборе стран. Антарктический договор и ничейная земля не заменяются колониальной гонкой.

## Защита живого состояния

- Еженедельная быстрая проверка ищет недопустимые числа до политических решений.
- Расчёты давления и гражданских войн отдельно отказывают при нечисловых значениях.
- Управляемая ошибка прерывает симуляцию, показывает понятное сообщение и оставляет
  диагностический снимок. Снятие паузы не продолжает частично выполненный день.
- Перед сохранением проверяются поля и свойства, включая исторические записи.
  Обычные сейвы не разрешают именованные NaN/Infinity.

Это не автоматическая подмена повреждённых чисел нулями. Достоверно восстановить
старую историю без хорошего снимка невозможно.

## Хороший сейв не заменяется плохим

`SaveSystem` проверяет данные до замены основного файла. При нарушении создаётся
отдельный диагностический файл с уникальным именем; только там допустимы именованные
нечисловые значения, чтобы оставить оригинальную причину. Он не появляется в архиве
кампаний как пригодный для игры слот. Последний хороший автосейв остаётся.

Короткие массивы истории/населения отклоняются, а не заполняются мусором из памяти.
Старая объектная запись с отсутствующими числовыми полями получает определённые нули.
Отдельный экспорт сценария сохраняет полную схему редактирования: сжатие сейва
не удаляет требуемые автору `MapIndex` и цвет.

## Размер и совместимость

По умолчанию используется сжатый `.bdfsave`. `SaveDefaults` опускает только значения,
совпадающие с новым экземпляром соответствующего типа, сохраняя нестандартные defaults,
например `-1` для отсутствующей цели. Текстовый JSON остаётся выбором для редактирования.

На копии реального сейва Германии за 10 марта 2138 года:

| Представление | Размер |
| --- | ---: |
| Исходный большой файл | 236,2 МиБ |
| Новый сжатый `.bdfsave` | 17,4 МиБ |
| Новый редактируемый JSON | 164,2 МиБ |

После повторной загрузки совпал отпечаток `E4B1EEEA76B64B5A`; исходный файл не изменялся.
Эти размеры относятся к одной кампании. История и отношения по-прежнему занимают место;
улучшение формата не означает постоянный размер кампании независимо от событий.

Конечные старые данные с совместимой геометрией загружаются. Разные наборы ID провинций
безопасно отклоняются без удаления файла: универсального переноса нет. Сейв с уже
записанными NaN/Infinity не объявляется исправным после одного обновления.

## Проверки разработчика

```powershell
dotnet run --project Tools/FormableTests -- --integrity-only
dotnet run --project Tools/FormableTests -- --release-only
dotnet run --project Tools/SimBench -- --integrity-save "C:/path/to/campaign.bdfsave" 365
dotnet run --project Tools/SimBench -- 365 20261008 --soak --out .fennara/soak.json
```

`--integrity-save` читает файл и прогоняет кампанию в памяти. Дни/seed у SimBench —
**первые два позиционных аргумента**, перед `--soak`, не `--days`/`--seed`.

Изолированный прогон исправления прошёл 5600 дней от старого снимка 2118 года
до 24 февраля 2134 года: проверенные числовые поля оставались конечными.
Позднейшие UI-изменения не входили в этот ранний бинарник. Тесты последней версии
отдельно проверяют кодек, сохранность хорошего автосейва, разделение страны и отказ
продолжать аварийный день. Столетний баланс требует нескольких сидов.
