# Сценарные переключатели механик

В `common/defines/*.json` добавлены две таблицы. Они объединяются по ключам между
файлами и модами: изменение авиации не сбрасывает артиллерию.

```json
{
  "Features": { "aviation": false, "drones": false, "air_defence": false },
  "FeatureUnlocks": { "aviation": "flight_ready" }
}
```

Подключены `long_range_forces` (главный выключатель), `aviation`
(пилотируемые аппараты), `drones`, `artillery`, `air_defence`. Каждый род независим:
выключение авиации само по себе не выключает дроны или ПВО. Для ранней эпохи выключите
их отдельно или отключите `long_range_forces` целиком.

Также подключены `navy`, `research`, `construction`, `recruitment`, `decisions`,
`events`, `politics`, `movements`, `colonisation`, `subjects`, `formable_nations`,
`secession`, `war_damage`, `war_weariness`. Они блокируют соответствующие новые
приказы и/или периодические системы. Флот исчезает с карты и из сводки; отдельные
экраны исследований, решений и управления скрываются. Общие экономические и
военные экраны остаются: выключение строительства не выключает всю экономику.
Существующие отношения, здания, технологии и сухопутные армии не удаляются.
Отмена заказов и ответы на уже ожидающие события по умолчанию остаются доступны.

Для дополнительных связей есть три объединяемые таблицы:

```json
{
  "Features": { "my_military": false },
  "FeatureCommands": { "SetArmyStanceCommand": "my_military" },
  "FeatureSystems": { "MilitaryOperations": "my_military" },
  "FeatureScreens": { "Military": "my_military" }
}
```

Ключи — точные имена классов команд/систем и внутренних экранов, не переводы.
Пустая строка снимает привязку. Все существующие `ICampaignCommand.Apply` и
периодические `Tick(Campaign)` проверяют привязки. Пользовательский код проверяет
`FeatureEnabled` самостоятельно. Это не универсальное удаление произвольного кода:
зависимости нового мода (например, логистика без флота) нужно проектировать явно.

Условие находится в `common/scripted_triggers/*.json`:

```json
{
  "flight_ready": {
    "min_year": 1903,
    "tags": ["RUS"],
    "min_technology.joint_air_ground_control": 1
  }
}
```

Это пример структуры, а не исторический баланс: замените технологию на свою.
Все условия должны выполняться у одной страны. Если подходит хотя бы одна страна,
механика включается **для всей кампании**, не только для неё. Проверка раз в игровой
день, без случайного выбора события. Ошибочное, пустое или отсутствующее условие
не включает механику. Цепочка зависимых включений развивается в следующие дни,
не зависит от порядка ключей. Для полностью ручного управления оставьте правило пустым (`""`).

В событиях, решениях и `common/scripted_effects`:

```json
{ "effects": { "feature.aviation_set": 1 } }
```

`0` отключает, `1` включает. Условия `min_feature.aviation: 1` и
`max_feature.aviation: 0` проверяют состояние. Если автоматическое правило осталось
и всё ещё выполняется, ручное отключение может отмениться на следующий день.

Новые модовые механики могут использовать свои ключи (буквы ASCII, цифры, `_`, до
80 символов). Необъявленный ключ выключен. Тип формирования получает дополнительный
`"required_feature": "experimental_air"`; его стандартные переключатели тоже должны
быть включены. GDScript API: `feature_enabled(id)` / `set_feature(id, bool)`;
C# corecode: `Campaign.FeatureEnabled` / `SetFeature`. Произвольный ключ не отключает
чужую систему автоматически: собственный обработчик должен проверять его.

Отключённые формирования и заказы **не удаляются**. Они отсутствуют на карте,
в списках, фильтрах, наборе и боевой поддержке; не получают задания ИИ, не тренируются,
не теряют/не восстанавливают состояние. Новые приказы отклоняются ядром. При включении
возвращается прежний состав и состояние; пропущенные дни подготовки не начисляются.
Изначально выключенные рода не создаются стартовым генератором. Включение позднее
не выдаёт бесплатных войск — их нужно набрать или задать в истории сценария.

Состояние, начальные переключатели и правила включения сохраняются, включая сетевые
снимки; изменения входят в проверку рассинхронизации. Старые сохранения без этих полей
сохраняют прежние включённые механики. Консоль: `feature`, `feature aviation off`,
`feature aviation on`; изменение через консоль блокируется в сетевой игре.

Готовый выключенный шаблон: `mods/_templates/era_features`. Сам по себе он не превращает
сценарий 2024 в средневековый: дату и исторический контент задаёт отдельный сценарий.

Проверка: `dotnet run --project Tools/ArmyInteractionTests -- --features-only`.
Проверки ядра включают запрет приказов, отсутствие боевой поддержки,
сохранения, условия открытия и возобновление подготовки без начисления пропущенных дней.
Живая проба `.fennara/scripts/runtime/feature_switch_regression.gd` также прошла:
авиация скрывает 3 из 8 формирований и свой фильтр в обеих проекциях; главный
выключатель закрывает панель и скрывает навигацию/радиус; включение возвращает 8
формирований. Каталог карты теперь сохраняет исправленную сетку при неизменных
исходниках; общие `--support-only` проверки также проходят.

Также исправлен старый разбор типа `air_defence`: подчёркивание в JSON больше не
превращает зенитно-ракетную бригаду в `Ground`. Живая повторная проба через
`feature_switch_regression_v2.gd` подтвердила отдельный фильтр ПВО и переходы
5 → 4 → 5 карточек при его выключении/включении, с выключенной авиацией.
