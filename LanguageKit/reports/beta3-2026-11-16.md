## Read these results carefully

- **Which bindings were "regenerated".** Rust (gdext `api-custom`) and Luau dump the API from
  the Beta3 engine at build time. Zig binds against gdzig's vendored **4.7.2** snapshot even
  when given the engine path; Go uses graphics.gd's baked bindings; Lua uses the godot-cpp
  **4.6** API bundled with lua-gdextension; Odin and Sandbox use the C interface directly.
  Those four work on Beta3 because the GDExtension interface is forward-compatible (and
  identical between Beta2 and Beta3), not because they were regenerated.
- **Nim and Kotlin were not rebuilt.** Their Beta1 artifacts load and pass; the Doctor labels
  them `-PREBUILT` so they are not confused with a rebuild.
- **A smoke test is small.** Each probe checks registration, a few calls (including the
  64-bit value 4294967297 where the probe has it), instance lifetime and a clean exit. It is
  not the full API, hot reload, or (for Sandbox) a security review.
- **Cold `--import` crash, not caused by the languages.** A plain first `--headless --import`
  exits `-1073741819` (access violation at shutdown) on Beta3 for AllSix, the Odin probe and
  **an empty project with no extensions**, and on Beta2 for the Odin probe as well (two runs
  each). The kit already avoids it: `Invoke-KitEditorBootstrap` runs a short headless editor
  first, then the import, and every probe above went through that path
  (`EDITOR_BOOTSTRAP cold_exit=0 warm_import_exit=0 errors=0`).

### Sandbox moved to `main` (owner's decision, 16 Nov)

The recipe no longer downloads the v0.60 release archive. `adapters/sandbox/build.ps1` now
builds everything from `4f9c73d6`: the host DLL (MinGW), the SafeGDScript compiler guest
`gdscript.elf` (cross-compiled to RISC-V with `zig c++`, which upstream's CMake supports; upstream
CI uses riscv64 GCC 14 on Linux) and the addon files (tracked `bin/addons/godot_sandbox`, plus
`LICENSE` and `THIRDPARTY.txt`, as upstream's `release.yml` does). The one download left is
`generated_api.hpp` from godot-sandbox-programs v0.1, checked against its published SHA-256
`b4e0a6f7…655c`.

What went wrong first: a restricted Sandbox compiles scripts with `gdscript.elf` *inside* the
sandbox and finds its `compile` function through the ELF's `.symtab`. Zig's linker turns
upstream's `-Wl,--strip-debug` into a full strip and drops `.symtab` unless it links with `-g`,
so the first build failed with `ERROR: Function not found: compile (Added to the public API?)`,
`SafeGDScript: : the GDScript compiler sandbox failed with call error 1`, and the probe hung until
its own process was stopped. `zig objcopy --strip-debug` is `unimplemented` for this target. The
recipe now links with `-g` and runs `adapters/sandbox/strip-debug.py`, which removes only the
non-loaded `.debug_*` sections (13 537 912 → 5 139 104 bytes), moves the `PT_RISCV_ATTRIBUTES`
segment with its section, and refuses to write if any loaded byte other than the header fields
or any of the 86 357 symbols changes, or if `compile` is not exported. Release v0.60's own
`gdscript.elf` is 3 928 776 bytes (GCC build).

The probe proves the source-built addon works on Beta3. It does not exercise the new refusals
(the mod loader those tests use needs manifests and traits); upstream's `Unit Tests` workflow,
which contains them, passed on `4f9c73d6` (run 43373963201).
