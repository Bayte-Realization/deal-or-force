for the three adapters actually exercised here. Target:
`4.8.beta2.mono.official.cafc17a19`, Windows x64.

The large scalar case is **4294967297**, not merely INT32_MAX. Passing small
arithmetic does not prove a correct Godot integer boundary. Both Go and Zig
passed the larger value. py4godot passed the earlier small-integer cases, but
failed this boundary; import and shutdown also reported leaked objects and
still-registered PyLanguage/PyScriptExtension/PyResourceFormatLoader/Saver.
An exit code of zero with a success print is not accepted if cleanup errors follow.

## What was improved

- Real Zig and Go class/method probes replace startup-only placeholders.
- Zig: correct 0.17.0 compiler requirement from the pinned manifest (the README
  was stale), namespace `godot.class`, valid package fingerprint, relative local
  dependency, explicit engine path and process-local compiler PATH for bindgen.
- Go: actual extension rather than only the `gd` build tool; pinned module/sums;
  optional `-BuildTool`; correct Node package, explicit lifetime and scoped
  C compiler/cache/environment. System Go 1.21.4 was not replaced.
- Python: release archive extraction is bounded, rejects wrong hashes/symlinks,
  retains the required `addons/py4godot` layout and never installs global pip
  packages. Source builds use the other pass's private venv. Runtime probes
  invoke Python; merely loading GDScript is no longer considered proof.
- The Meson candidate retains compatibility method hashes and new global integer
  constants, including exact INT64 bounds. Missing optional constant descriptions
  work without a documentation dump. Unexpected fields and malformed hashes are
  still rejected. Patch, original MIT licence, source pin and eight tests ship
  in `adapters/python-meson`; no upstream PR was opened.
- Doctor separates historical Beta1 evidence from exact-engine Beta2 smoke tests.
  The updater backs up old source files, detects source/destination changes,
  records SHA256 preimages and leaves projects, caches, engine and game intact.

`-Language go`. It only opens an editor when the user runs it. The old AllSix
workbench is preserved, not silently rewritten or recertified for Beta2.

On a fresh source-only clone, install private tools with
`workbench/install-portable-toolchains.ps1` first. Official archive hashes are
pinned in `toolchains.windows.lock.json`. MSVC/Windows SDK remain an explicit
external prerequisite for Rust; no Visual Studio installation is performed.
Build-local restores process environment after each adapter. Native output is
not committed. Upstream sources retain their own licences.

## Limits and next slice

This does not certify the entire native API, exports, hot reload, coexistence,
thread safety, every platform or downloaded-mod safety. Rust linker messages
produced two compiler warnings, not runtime errors. Other adapters retain their
dated Beta1 results, including godot-sandbox v0.60; latest sandbox main was
reviewed but not rebuilt/certified here. No performance gain is inferred from
these tiny ABI probes, and no game tick/save/network logic was migrated.

The Meson branch's real HEAD was 2026-02-26. Its development manifest requires
Python 3.14+, while its default engine option is 4.4.1. The old README is not a
Beta2 certificate. A full native Meson port, generation of the exposed global
constant API, export and lifecycle tests remain open. An earlier experiment with
`--dump-extension-api-with-docs` returned nonzero and was not counted as success;
the retained gate uses the successful ordinary API dump and checks optional docs.

For the game: Rust/Zig suit measured, bounded native batches; Go suits tooling
and separately scoped services; Python suits validation, analysis and offline
content pipelines. Keep one campaign authority in C# and require representative
equivalence/performance tests before moving production work. The outstanding
war/territorial integrity and world-cache isolation work remains on the game plan.
