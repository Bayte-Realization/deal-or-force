# Языки для Godot 4.8 Beta2 .NET

[English](GUIDE.md) · [Русский](GUIDE_RU.md)

Установленная цель: Windows x86-64, `4.8.beta2.mono.official.cafc17a19`
(`C:/GodotEngineNet 4.8-Beta2/Godot_v4.8-beta2_mono_win64_console.exe`).
Совместный прогон 16 октября был на `4.8.beta1.mono.official.4d10419ca`
([reports/native-bindings.md](reports/native-bindings.md)).
Таблица пинов и команд на 29 октября — в [GUIDE.md](GUIDE.md).
F#, Rust, Go и Zig на Beta2 прошли свою пробу. Python не собирался: последний релиз py4godot — 4.7-alpha21.
Это лаборатория, не тик кампании. Правила штурма на F# остаются.
Медиана C# на бенчмарке владений была около 2629 мс, Rust — около 3657 мс.
Это набор исходных адаптеров и локальных примеров, а не новая официальная
дистрибуция Godot. Исполняемый файл движка и GodotSharp не заменяются.

## Что именно работает

Строки ниже — совместный прогон 16 октября на Beta1, не проверка Beta2 от 29 октября.

| Язык | Реальная интеграция | Проверенный вызов |
| --- | --- | --- |
| Luau | ScriptLanguageExtension, ресурсы `.luau` | Типизированный метод, модуль, независимые экземпляры, native Callable |
| F# | Библиотека .NET 10 через C#-мост | Пакетный расчёт, независимое состояние, отказ некорректному вводу |
| Rust | Скомпилированный GDExtension, API из установленного 4.8 | Native-класс, PackedInt32Array, отрицательный и пустой ввод |
| Nim | Скомпилированный GDExtension, исправленный Windows bootstrap | Native-класс, пакетный расчёт, корректное завершение |
| Odin | Низкоуровневый C ABI GDExtension | Регистрация класса, Variant/ptrcall, владение/освобождение объектов |
| Kotlin | Godot-JVM RC4 GDExtension, скомпилированные JVM-классы | Загрузка `.kt` ресурса и вызов зарегистрированного метода |

Все шесть прошли один совместный процесс настоящего .NET Godot: первый
редакторный bootstrap, повторный импорт, вызовы и завершение с кодом 0, без
Godot ERROR. Дополнительная общая проверка прошла также с **отдельным Lua 5.4.8**
и **Godot Sandbox**. Lua — не замена Luau. LuaJIT в этом проходе не проверялся.

F# не добавляет Attach Script для `.fs`; Rust/Nim/Odin — не новые языки
сценовых скриптов. Их код редактируется и компилируется внешними инструментами,
а зарегистрированные классы доступны Godot. Для Kotlin нужны сборка/регистраторы
Gradle и Java. Расширения активируются **в проекте**, не глобально от присутствия
DLL рядом с Godot.exe. Разные языки не получают весь API 4.8 автоматически.

## Локальный запуск у автора

Комплект устанавливается рядом с редактором:

```text
C:/GodotEngineNet 4.8-Beta2/LanguageKit/
  Open Workbench.cmd
  projects/AllSix/       # локальная собранная лаборатория, не в Git
  adapters/             # примеры, рецепты, патчи, лицензии
  reports/              # ограничения и результаты каждого направления
```

`Open Workbench.cmd` открывает **отдельный** редактор лаборатории, не закрывая
основную игру. Двойной щелчок не переносит эти расширения в любой другой проект.
PowerShell 7, .NET SDK 10 и Java должны оставаться установленными. На проверенной
машине выбран JDK 25; финальный пример Kotlin генерирует Java 17 bytecode.
Смена машины/Java требует указать свои пути в параметрах `open-workbench.ps1`.
Этот launcher открывает исходники; вычислительная регрессия запускается отдельно:

```powershell
./language-kit.ps1 -Action Doctor
./tests/kit-tests.ps1
# Для уже собранной лаборатории, из каталога LanguageKit:
$env:JAVA_HOME = 'C:/Program Files/Eclipse Adoptium/jdk-25.0.2.10-hotspot'
& 'C:/GodotEngineNet 4.8-Beta2/Godot_v4.8-beta2_mono_win64_console.exe' `
  --headless --path ./projects/AllSix --script res://combined_probe.gd -- `
  fsharp luau rust nim odin kotlin
```

Последняя строка успеха: `LANGUAGE_WORKBENCH_PASS ... failures=0`.
Любой ERROR, аварийное завершение или ненулевой код — провал, даже если до него
успел появиться PASS. Не запускайте проверки поверх открытой лаборатории во время
пересборки её DLL. Основной пользовательский редактор ни один probe не завершает.

## Получение исходников и пересборка

Публичный репозиторий хранит рецепты, исходники примеров, compatibility-патчи,
лицензии и точные ревизии семи upstream-проектов. Бинарники/компиляторы/сборки игры
в Git не входят. Для получения исходников выполните Fetch по `sources.lock.json`:

```powershell
./language-kit.ps1 -Action Fetch
./language-kit.ps1 -Action Build -Languages fsharp
./language-kit.ps1 -Action Probe -Languages fsharp
```

Для native-адаптеров нужны соответствующие компиляторы и Windows SDK; подробные
параметры каждого — в `adapters/<язык>/README.md`. `-BuildOptions` позволяет передать
пути portable-компиляторов без изменения системного PATH. Kotlin и Sandbox требуют
своих build tools; Maven SNAPSHOT-зависимости Kotlin ещё не зафиксированы по
контентным checksum, поэтому полная воспроизводимость релизов пока не заявлена.
Сборщики применяют патчи только к выбранным pinned checkout; не используйте для
этого свою незавершённую ветку upstream. Source Fetch не сбрасывает иной checkout.

После сборки `create-workbench.ps1 -OutputDirectory <новая-пустая-папка>` принимает
словарь `-Addons @{ luau=<addon>; rust=<addon>; nim=<addon>; odin=<addon> }`,
`-KotlinProject <собранный-проект>` и `-JavaHome <JDK>`. Флаги
`-EditorBootstrap -Probe` проверяют совместимость собранной комбинации.
Optional ключи `lua` и `sandbox` не обязательны для шести запрошенных языков.

`InstallKit` копирует только исходники, отказывает при отличающемся существующем
файле, не перезаписывает движок и не активирует DLL в живой игре. Кэши/`projects`
не копируются в исходный комплект. GPL-3.0 относится к нашему обвязочному коду;
чужие библиотеки сохраняют MIT/MPL-2.0/Apache-2.0/BSD-3-Clause и свои notices.

## Исправления и границы готовности

- Nim: Windows runtime/allocator инициализируются до первого Nim callback;
  добавлен `stdint.h`, отключён захват глобальных signal handlers.
- Luau: `.luau`/`.mod.luau`, правка vararg Callable. Upstream архивирован,
  поверхность API старая; только проверенные editor/debug mapping.
- Lua: `LuaTable.get/set` заменены на `get_value/set_value`, чтобы не затенять
  унаследованные методы Object, с обновлением документации.
- Sandbox: отдельные `sandbox_*` alias и ранняя регистрация языков. Пройден
  ограниченный арифметический пример, **не** аудит злонамеренных модов.
- Odin: работоспособный прямой ABI вместо неработающего на новом Odin полного
  генератора Temple/Godin. Полные generated wrapper и Godin не объявлены готовыми.
- Rust: минимальные bindings с API/header из конкретного установленного движка.

В Beta1 воспроизводилась проблема холодного немедленного импорта, согласующаяся с
[Godot #111048](https://github.com/godotengine/godot/issues/111048): завершение
может опередить deferred-генерацию документации расширений. Наш bootstrap заранее
создаёт производный список известных расширений, даёт редактору 300 кадров с
frame-delay 20ms, затем требует обычный импорт и runtime без ошибок. Это обходной
запуск/CI-рецепт, **не исправление исполняемого файла Godot** и не гарантия общего
отсутствия гонок. Наблюдавшиеся неудачные запуски сохранены в отчётах как неудачи.

Основной проект уже содержит старый Fumohouse Luau с `.lua`. Его нельзя загружать
рядом со вторым Fumohouse: native-типы имеют одинаковые имена. Суффикс `.luau`
разделяет новый Luau и gilzoide Lua, но не решает дублирование двух Luau-расширений.
Миграция старых модов/сейвов — отдельная проверяемая задача при закрытом редакторе.
Текущий addon игры не заменён, существующие моды не переименованы.

Standalone exports/release templates, hot reload, все API/ОС, долгие кампании,
сетевой determinism и вредоносный код ещё не сертифицированы. Native/JVM/.NET-код
доверенный: обычный GDExtension не является песочницей скачанных модов.

## Рефакторинг игры: где действительно есть смысл

Состояние мира, порядок команд, сохранения, fingerprints и сетевая авторитетность
остаются в C#. Не делаем шесть runtime обязательными всем игрокам и моддерам.
Языки подключаются по задаче, с managed reference и отключаемым backend.

| Направление | Кандидаты | Что нельзя обещать без замера |
| --- | --- | --- |
| Rust | Только исключительные сложные задачи с измеренной пользой и малой изолированной границей | Обязательность Rust для повседневной разработки или выигрыш от одного native-вызова на провинцию |
| Nim | Численные буферы, преобразование региональных данных, offline-генерация | Полный API 4.8 и отсутствие GC/allocator затрат |
| Odin | Raster/overlay kernels, плотные буферы графики, preprocessing | Готовый высокоуровневый toolkit, который upstream пока не предоставляет |
| F# | Чистые правила, eligibility, экономические/дипломатические оценки и валидация | Автоматическое ускорение против C#: это тот же .NET/JIT |
| Luau | События, решения, модовые формулы через малый capability API | Безопасность произвольных библиотек и частых host-вызовов |
| Kotlin | Валидаторы контента, сложные инструменты, использование JVM-библиотек | Дешёвый startup/RAM/JNI; JVM не нужен в каждом ежедневном tick |

Правило автора: **Rust не становится повседневным языком проекта**. Строгость
компилятора не является нестабильностью runtime; реальные риски — FFI, владение,
платформенные сборки и сопровождение. Измеренная польза должна оправдать их.

Первый реальный пакетный эксперимент уже выполнен: связность владений на
Rust и Odin, единый ABI и C# reference, 35 295 провинций плюс малый/стрессовый
ввод. Оба совпали по результатам, но не выиграли по медиане у существующего C#.
Исходники и проверки остаются в `kernels/ownership`, экспериментальный host —
в `Tools/OwnershipKernelBench` репозитория игры. **В игровом Corridors нет native
hook, никакая DLL этого эксперимента игроку не нужна.** Такой же порт на Nim
пока не нужен: дублирование алгоритма не устраняет цену упаковки/проверок.

Более уместные следующие роли: Odin — отдельный плотный raster/overlay после
профиля; Nim — проверка/преобразование данных для моддеров; F# — компактные чистые
боевые правила; Luau — опциональные формулы на копии данных. Существующие JSON
правила остаются простейшим путём, языки не обязательны моддерам.
Чистый [F#-эксперимент боевых правил](experiments/assault-rules/README.md) уже
сравнён с фактическим C# assessor: 624 502 случая без расхождений. Это проверка
эквивалентности и читаемости, не внедрение в игру или замер ускорения.
Текущий игровой `EngineScriptMod` принимает `.lua`; события/формулы из комплекта
не становятся доступными ему автоматически. `enact_policy/manage_debt/add_course_shock`
идут через очередь, но старые `set_feature/set_nation_number/set_define` меняют
состояние напрямую: весь API нельзя объявлять queued или безопасной песочницей.

Для дальнейших kernels замеряем время с копированием через границу,
allocations, p50/p95, память;
прогоняем малый/типичный/стрессовый ввод. Integer overflow, float rounding, порядок
обхода и ошибки должны иметь явный контракт. Затем сверяем команды/отпечатки
кампании и replay, включая сохранение/загрузку и сеть. Если выигрыш не оправдывает
сложность — оставляем C#. Арифметический smoke-test не доказывает ускорение игры.

Приоритет не меняется: комфортный интерфейс, сильный ИИ, стабильная симуляция и
простой моддинг. Добавление языков — инструмент этих целей, не самоцель.
